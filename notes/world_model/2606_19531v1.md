# ImageWAM: Do World Action Models Really Need Video Generation, or Just Image Editing?

## Insight
Observation：机器人 WAM 用未来视频作为中间表示很直观，但 dense multi-frame token 昂贵，且容易把容量花在背景/外观/长时未来细节上；错误想象还会误导动作预测。

推论：对许多 manipulation task，关键不是完整未来视频，而是“当前图像到任务目标状态的指令引导视觉变化”。图像编辑模型的中间 KV cache 可能是更紧凑的 world-action context。

## Motivation
论文挑战 video-generation-based WAM：世界动作模型是否真的需要生成视频？它解决实时机器人控制中的效率、动作相关性和错误未来想象问题。

同行 WAM 多用视频生成/未来帧 rollout，再接 IDM/action decoder。ImageWAM 改用 pretrained image editing backbone。

## Method
流程：
- 输入当前 observation 和语言指令。
- 图像编辑 backbone 执行 instruction-conditioned denoising，但推理时不解码目标图像。
- Action Expert 读取编辑过程产生的 KV cache，通过 joint attention 预测未来 action chunk。
- 可基于 OmniGen2、Ovis-U1、FLUX.2 等 image editing backbone。

创新点是把 image editing 的“source-grounded visual transformation”当作 world-action intermediate，替代 dense future video。

## Experiment
评估 RoboTwin 2.0、LIBERO、LIBERO-Plus 和真实双臂机器人。

结果：
- RoboTwin 2.0：ImageWAM clean 93.20、randomized 93.56、avg 93.38，略优于 FastWAM 91.83。
- LIBERO：avg 98.4，接近/优于多个 VLA/WAM baseline。
- LIBERO-Plus：FLUX.2 4B 版本 avg 83.1，明显高于 FastWAM 51.5，也强于多种 VLA baseline。
- 真实机器人四任务：ImageWAM avg 84.5，高于 π0 55.8、π0.5 72.3、FastWAM 79.0。
- 效率：ImageWAM 263ms、9.72 TFLOPs；FastWAM-IDM 1081ms、63.65 TFLOPs；FastWAM one-step 302ms、13.21 TFLOPs。

## Value
价值在于提出了一个很实用的反命题：WAM 的中间表示未必需要“可观看的视频”，只要能提供 task-relevant transformation context。对机器人控制尤其有用。

局限：严格说它弱化了 world model 的显式时间预测能力；对需要长期物理 rollout、规划或 counterfactual simulation 的任务，image editing cache 可能不足。

# Do We Still Need Reinforcement Learning When We Can Read the World Model?

## Insight
观察：若环境实现的状态转移、奖励和任务规则可读，代码代理能据此直接写出控制程序，在线交互主要用于验证/修改，而非梯度训练。作者通过“可读源码/仅任务说明”的配对实验和从源码推断 FourRooms 墙体、Kitchen 任务完成条件的案例说明其价值；但两组在许多任务上同样成功，不能推论源码访问普遍必要，更不能推论 RL 普遍不需要。

## Motivation
RL 即使借助学得的世界模型，也往往耗费大量交互来优化策略。论文问：在可直接访问模拟器源码的特殊条件下，通用代码代理能否理解动力学和奖励、编写可执行策略，节省任务专用 RL 训练？该问题对可读仿真环境的策略开发有意义，与从视频学习世界模型是不同设定。

## Method
把环境源码定义为“可读世界模型”，让 Codex 代理分析转移、奖励、观测与终止逻辑，输出规则式或使用离线数据拟合的非神经策略。在线任务用最多 1600 次开发回合试跑、修订，并按完整 100 回合开发验证选策略；离线任务仅用固定数据和源码构造/检验策略。最终独立评测时策略只用与 RL 基线相同的观测，不调用 LLM。方法本身没有统一的新规划算法或学得的预测模型，贡献是跨任务实证比较。

## Experiment
对 SMAC、MPE、MiniGrid、Box2D 共 16 个在线任务，以及 D4RL、BabyAI 离线任务做三次独立策略构造；指标为胜率、成功率、回报、达标交互步数。在线 16 项中 15 项优于相应无模型 RL；MiniGrid DoorKey 达标耗 1,789 步，对 DreamerV3 40 万步，但代理已读环境实现。D4RL Maze2D/Kitchen 平均标准分 176.9/90.2，MuJoCo/Adroit 平均仅 59.9/17.4，弱于若干离线基线；BabyAI 六项平均成功率 99.28%。源码访问消融：16 个在线场景中改善 8、劣于无源码 3、持平 5；Kitchen-partial 从 40.92 提至 96.17。稀疏奖励和视野变化可在若干任务适应，但大规模 SMAC 迁移到 27m_vs_30m 胜率为 0，原有策略在某些较窄视野下骤降。离线 RL 比较部分沿用已发表分数，计算成本另以 token 费用估计。

## Value
启发是：当有可信的可读模拟器时，可用代码代理合成透明的规则控制器，作为学习策略的强基线或初始化；比较学得的视觉世界模型规划时必须说明源码特权、开发交互和计算成本。本研究不解决视频/3D/JEPA/Dreamer 模型的学习、生成或不确定性问题。

## Strengths
跨离散、连续、多智能体及离线任务；独立评测与源码访问消融；展示实际策略代码、失败迁移和代理 token 成本。

## Weaknesses
源码揭示动力学与奖励，和仅靠观测学习的 RL 信息条件明显不同；代码代理、搜索、数据拟合本身有未折算成环境步数的成本；大量复杂连续控制及迁移场景效果不佳，部分基线采用文献分数，缺少统一预算下比较。

## Future Work
作者提出研究不完整或不确定的可读模型，利用交互反馈提高策略可靠性，并可把合成策略作为后续 RL 的起点；还需评估源码与真实环境动力学不一致时的失效。

## Rating
创新度评分：2/5 - 跨任务实证充分，但核心是现有代码代理读取模拟器后编写策略，缺少新世界模型或通用算法。
相关度评分：1/3 (Tangential) - 仅在规划/控制基线层面有间接启发，不研究视频、3D 或隐式世界模型本身。

## TL;DR
代码代理读取模拟器源码后可低交互合成策略，但依赖特权环境知识，且连续控制较弱；对世界模型研究可选读。

# ExeWorldBench: Benchmarking Code-Based Executable 3D World Modeling

## Insight
观察到模型能产出可运行 Blender 代码，也可能只复现外观而没有正确的机械连接和因果传递。论文把可执行 3D 建模拆成单机构、多级因果组合、从目标自主合成三个难度层级，实验显示代码可执行率提高后，结构与因果评分常仍很低；执行链越长，错误传播越严重。这是评测设计和经验结论，没有理论证明。

## Motivation
既有物理问答仅测试推断，视觉转代码偏静态几何，行为基准常只覆盖单物体或简单二维运动；都不足以判断模型是否构造了能以接触、约束和连接产生目标行为的 3D 世界。对 3D 世界模型而言，外观与运动一致性之外的可执行因果性是关键评测维度。

## Method
T1 给单张机构图，要求写 Blender 程序重建完整运动；T2 给多机构参考，把 4–13 级部件连接成连续因果链；T3 从文字合成，其中 T3-1 给 4–12 个指定部件，T3-2 仅给目标、物理规则及状态/事件条件。数据由公开机构动画、原子部件库、模型生成和人工审核构建。评测先运行代码，再用视觉语言裁判对视觉结构 `V`、机构运动 `M`、分段可执行因果机制 `ECM` 打 0–10 分，T3-2 另计初始/过程/最终条件的目标满足率；失败代码计零，并报告仅可执行样本的条件分数。API 模型还接受只修运行错误的统一代码修复，以分离语法错误与建模错误。创新在评测目标与分层任务，而非新世界模型架构。

## Experiment
对比带编码代理框架与纯 API 的多个前沿模型，并分析修复前后、长链及补充运动参考帧。T1 中 GPT-6 Astra(Codex CLI) 可执行率 100%，`V/M=7.16/6.32`；纯 API 版经修复可执行率 58%→94%，运动分数 3.14→5.08。T2 中 GPT-6 Astra 纯 API 修复后可执行率 91%，`ECM` 仅 2.47；T3-2 同一模型修复后可执行率 91.67%，目标满足率 41.07%，而代理框架版为 90.14%。T2 的长链 ECM 随级数下降，补充视频运动帧增益也有限。附录显示部件库 15 类、850 次使用，其中坡道约占 30%。

## Value
值得精读其评测拆分：将几何、运动、因果交接和终态分别计分，适合为 3D 世界生成/仿真团队设计更能排除“好看但不工作”的测试。也提醒比较模型时将代码执行失败与物理理解失败分开。

## Strengths
同时覆盖观察驱动重建与目标驱动合成；引入多阶段接触和因果交接，难度更贴近可交互世界；展示修复前后与长时域误差，能定位失败来源。

## Weaknesses
机制样例集中于玩具式刚体链，部件库分布偏斜；T1 单张图可能不能唯一确定真实动力学。结构、运动和因果分数主要依赖同类 VLM 裁判，缺少充分的独立物理检验及裁判一致性分析；模型参与数据筛选、代码修复和评分，可能产生模型偏向。代理框架与纯 API 在工具和迭代能力上不等价。

## Future Work
作者希望基准推动能构建物理一致可执行世界的系统；未提出具体算法路线。可进一步增加真实物理验证、复杂接触场景与评测裁判可靠性。

## Rating
创新度评分：3/5 - 提出分层可执行 3D 因果评测，任务设计有新意，但评判较依赖模型裁判。
相关度评分：3/3 (Core) - 直接评估代码化 3D 世界模型的结构、动力学和目标行为。

## TL;DR
提出从单机构到目标驱动合成的可执行 3D 世界基准，揭示代码可运行仍难保证因果正确，值得精读。

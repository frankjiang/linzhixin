# Light Interaction: Training-Free Inference Acceleration for Interactive Video World Models

## Insight
核心观察：交互式视频世界模型中，"交互"本身天然提供了自适应计算的信号。具体有三个观察：
1. **Pose-aware retrieval similarity** 可区分 novel exploration（检索记忆无效，应丢弃）和 trajectory revisiting（检索记忆有效，应保留），不需要对所有帧等量使用空间记忆
2. **局部 latent dynamics**（相邻帧 latent MSE）反映时间上下文的有效长度——动态大时收窄窗口，稳定时扩大窗口
3. **Denoising step 间的冗余在 revisiting 时远大于 exploration 时**——revisiting 时中间去噪步骤可复用第一步输出，exploration 时不可

这三个观察统一在"trajectory-dependent adaptive computing"原则下，实现无需重训练的加速。

## Motivation
- 问题：交互式视频世界模型（如 HY-WorldPlay、Matrix-Game-3.0）生成长交互轨迹极其昂贵（HY-WorldPlay 生成 10s 视频需 >200s on A100），瓶颈来自增长的上下文记忆、二次复杂度注意力、重复去噪。
- 同行做法：KV cache 压缩方法（H2O、Scissorhands）用统一策略不区分场景动态；去噪缓存（DeepCache、FasterCache、TeaCache）不区分 exploration/revisiting，在新场景探索时引入伪影；稀疏注意力（SVG、LongCat-Video BSA）设计为双向而非因果，在 AR 生成中因 layout 转换和 gather/scatter 开销失效。
- 关键性：交互式世界模型要实现实时交互，推理加速是必须解决的工程问题。

## Method
三个互补模块：

**1. Adaptive Context Management（自适应上下文管理）：**
- **时间上下文自适应**：用最近两帧 latent MSE 的指数移动平均估计局部动态 D_t，动态大时缩短保留窗口 L_t = clip(L_m * kappa/(D_t+kappa), 1, L_m)
- **空间记忆自适应**：当 max pose-aware retrieval similarity < tau_pose 时判定为 pure exploration，丢弃检索到的空间记忆（因为无有效几何对应）

**2. Denoising Cache Acceleration（去噪缓存加速）：**
- 仅在 revisiting（max S_pose >= tau_pose）时启用缓存
- 对 K 步去噪过程，正常计算 step 0 和 step K-1，中间 step 1~K-2 复用 step 0 的输出
- 观察依据：revisiting 时相邻去噪步 relative L1 距离远小于 exploration 时

**3. Hardware-Software Co-designed 3D Block Sparse Attention：**
- 将历史 visual KV tokens 划分为 3D 时空 blocks (B_t, B_h, B_w)
- 对每个 query block，用 pooled proxy vector 计算与所有 K blocks 的相似度，TopK 选择保留比例 r 的 blocks
- 仅对历史 visual KV 做稀疏化，保留所有 text-conditioning tokens 和当前帧 tokens
- 三个 fused Triton kernels（Q-Prep、KV-Prep、Untile-Scatter）消除 layout 转换、gather/scatter、padding 开销，实现 1.40x 注意力加速

## Experiment
**实验设置：**
- 模型：HY-WorldPlay (480P I2V) 和 Matrix-Game-3.0 (720P I2V)
- 基线：SVG（静态稀疏注意力）、BSA（动态块稀疏）、TeaCache（去噪缓存）
- 评测：200 组 image-text pairs，forward-backward 和 left-right 两种轨迹

**HY-WorldPlay 结果：**
- 延迟 228.6s -> 88.24s，**2.59x 加速**
- PSNR 24.81（vs Original 基准），Self-Comparison PSNR 18.85
- VBench 0.8220 vs 原始 0.8190（保持甚至略有提升）
- 内存 76.57GB -> 54.66GB（节省 21.91GB）
- 所有基线（SVG/BSA/TeaCache）在此模型上实际没有加速（0.92x-1.12x），SVG 和 BSA 因 AR 约束引入额外开销

**Matrix-Game-3.0 结果：**
- 延迟 59.70s -> 37.07s，**1.61x 加速**（最快）
- VBench 0.7350 vs 0.7432，quality competitive

**消融实验（HY-WorldPlay）：**
- Context Mgmt (Full) 单独：1.58x 加速，quality 最好（PSNR 29.24 vs Orig）
- Denoising Cache 单独：1.15x，PSNR 35.16（最高保真）
- 3D Sparse Attn 单独：1.49x，有轻微质量下降但被 context mgmt 补偿
- 三者互补，联合达到 2.59x

**超参数分析：**
- Retained ratio 和 FOV threshold 控制 quality-efficiency trade-off，存在清晰的最优区间

## Value
- **工作价值中等偏上**：在交互式视频世界模型推理加速这一具体但重要的工程问题上，提供了一套完整的 training-free 方案。三个模块的设计基于合理的经验观察，互补性好。
- **对我们的启发**：
  1. 交互本身提供了自适应计算的天然信号（pose similarity），这一思路可推广到其他交互式生成场景
  2. Exploration vs Revisiting 的区分是处理长程生成的关键——不同状态下计算需求截然不同
  3. AR 设置下稀疏注意力的 gather/scatter 开销是实际瓶颈，需要 hardware-aware kernel 设计
  4. 去噪缓存的有效性高度依赖场景状态，盲目缓存在 exploration 时有害
- **局限**：依赖 camera-pose-aware similarity 信号（需要模型或外部估计提供）；仅验证了 K<=4 的短步去噪模型；加速效果与底层模型的内存组织和执行结构高度相关

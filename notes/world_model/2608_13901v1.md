# Ontology-Grounded World Models for Failure Diagnosis and Closed-Loop Repair in Physical AI Systems

## Insight

观察：feature/event scalar 能排序候选，却不能说明哪一个任务谓词失败、涉及哪些实体、应调用哪类修正或修正后是否被原生任务谓词接受。推论：在世界模型和修正器之间加入 typed predicate record，可保留失败语义与 provenance，并把 proposal、application、verification 分离。论文用 task-local TBox/ABox、确定性诊断/路由和 verifier gate 实现该接口；但实验没有隔离 ontology 本身的因果收益，因此证明的是完整系统可记录并执行流程，而不是 ontology 提升成功率。

## Motivation

EV-WM 以视觉特征 rollout 和事件分数做规划，难以表达 `in_region(plate, stove_front)` 这类精确失败条件。机器人恢复需要从预测或模拟器状态，经过明确诊断、兼容路由，到修正后原生谓词验证。问题对可审计 Physical AI 有价值；同行包括 TAMP、KnowRob、neuro-symbolic interface 和 recovery policy。本文定位很克制：不是新 world-model backbone、通用 ontology reasoner 或新控制策略，而是 EV-WM 上层接口。

## Method

TBox 定义 Object/Region/Joint、relation/constraint/failure/route 等类型和谓词签名；任务规格编译为 required ABox，世界模型预测或 simulator state 分别通过 source-specific grounding 生成带 provenance 的 observed ABox。`Sat_T` 按极性、阈值和证据检查必需事实，未满足项生成保留谓词、参数、失败类别和 margin 的诊断记录；外部确定性 `Π_R` 映射到 route label。proposal 可来自学习器、启发式或规划器，application 明确区分 simulator mutation 与 controller execution，只有 native verifier 为真才 accept，否则在预算内 reground/retry/reroute。

PointMaze 用预测 fact 做候选评分；LIBERO-Goal 量化协议却固定一个 source/joint qpos-delta head，直接写 simulator qpos，每个 replay failure 只提一次修正；Task 76 的 OSC-Pose retry 仅是定性案例。创新是记录契约和 provenance 组织，不是新的本体推理或世界模型学习。

## Experiment

- PointMaze 对齐 50 trial：DINO-WM/EV-WM/Onto-EV-WM 成功率 0.90/0.94/0.94，后两者没有成功率提升；平均末状态距离 0.90573→0.61177。另一个 100% 结果同时增大搜索预算并改为 success-first，不可直接比较。
- LIBERO-Goal 每个 sampling seed 500 个 25-step window，checkpoint 固定。四个 seed 的 replay 成功 86.95±1.00%，直接 qpos 修正后的完整配置为 94.05±0.30%；2,000 window 的 261 个 replay failure 中救回 142 个（54.4%）。seed 仅改变评测采样，不是训练重复。
- 该协议与 label 构造池重叠、非 held-out、非 full episode；修正直接改变模拟器状态，不检验机器人策略能否实现。
- LIBERO-Plus 固定 10,030 task registry 上成功 8,526（85.00%），高于内部 DINO-WM+CEM 61.57%，接近 GAM 85.5；但跨架构文献表和完整系统对照无法归因 ontology。

## Value

对世界模型系统设计的启发是：把预测、失败语义、路由、应用方式和验收结果作为一等记录，避免把“候选分数高”误当“任务谓词满足”。这适合构建可审计恢复接口，也能与 JEPA/feature WM 拼接。但论文当前更像接口规范加系统展示，不能证明本体 grounding 改善规划或真实恢复，对核心视频/3D模型的直接价值中等。

## Strengths

- 对组件边界和 claim 很克制，反复区分 route label、state mutation、controller execution 与 task success。
- typed failure 保留原谓词参数、阈值和来源，比单 scalar 更可审计。
- 给出形式化记录、算法和不同协议的适用范围，避免把定性 trace 混入量化结果。
- LIBERO-Plus 覆盖大，且论文主动披露 seed、重叠数据和直接 qpos 操作等限制。

## Weaknesses

- 没有 ontology-only、typed-vs-untyped 或动态路由消融，核心贡献的因果效果完全未测。
- 量化 LIBERO-Goal 固定单一路由，ontology 不负责在线选择；成功提升可能全部来自 learned qpos head。
- 直接修改 simulator qpos 绕过动力学和控制，不能代表物理机器人可实现的 recovery。
- TBox/ABox 实际是枚举 schema 与任务特定映射，无通用推理、开放世界或运行时一致性检查。
- PointMaze 样本仅 50，成功率不变；LIBERO 不是 held-out full episode，文献横向表也非统一协议。

## Future Work

作者明确把 held-out generalization、ontology 组件因果隔离和真实机器人恢复留作未来工作。还需要量化动态多路由选择、controller-mediated 成功率、诊断准确性和接口审计收益。

## Rating

创新度评分：2/5 - typed grounding 与验证门作为系统接口有实用增量，但非新 world model，且关键 ontology 贡献没有被消融验证。
相关度评分：2/3 (Related) - 建立在 feature-space EV-WM 上并服务机器人规划/修正，但主体是符号诊断接口而非视频、3D 或 JEPA/Dreamer 模型本身。

## TL;DR

为 EV-WM 增加可审计谓词诊断与修正门，但因果证据弱，可选读。

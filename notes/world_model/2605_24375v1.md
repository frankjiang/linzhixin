# Distilling Game Code World Model Generation into Lightweight Large Language Models

## Insight
核心发现：SFT单独使用不足以提升GameCWM生成的整体质量（甚至可能因过拟合导致退化），但SFT+RLVR的两阶段后训练pipeline可以将GameCWM生成能力有效蒸馏到3B小模型中。RLVR在SFT之后应用效果最佳——SFT先教会模型API格式和代码结构，RLVR再通过执行反馈改善语义正确性。然而，复杂的不完全信息博弈（如Gin Rummy、Hand of War）对所有模型（含GPT-4o）仍极具挑战，语义正确率和信息处理得分极低（Qwen最佳仅5.3%），表明当前LLM缺乏生成忠实模拟博弈论逻辑代码的推理能力。

## Motivation
问题：用LLM从自然语言描述自动生成Game Code World Model（GameCWM，即实现博弈规则的可执行Python环境）是构建多智能体博弈环境的有前景方向。但现有方法（如GIF-MCTS）严重依赖前沿模型（GPT-4、Gemini 2.5 Pro）的推理时计算（迭代生成-测试-修复循环），可达性和可扩展性差。本文探索能否通过后训练将这种能力蒸馏到轻量模型中，消除对前沿模型和推理时迭代的依赖。

## Method
三个核心组件：
1. **数据集构建**：30个广泛形式博弈（extensive-form games），按难度分四级——简单完全信息（井字棋等）、中等完全信息（Y、Breakthrough等）、困难不完全信息（Leduc Poker等）、新颖/OOD博弈。每个样本包含API规范+自然语言规则+动作字符串+场景轨迹+ground-truth代码
2. **四层验证框架**：(i) 静态分析（API完整性、类型签名、编译）；(ii) 动态模糊测试（100轮随机rollout验证确定性、非终止逻辑、不可变性等）；(iii) 语义规则遵从（由前沿LLM生成5个场景trace，测边界条件和典型玩法）；(iv) 信息一致性（仅不完全信息博弈，验证resample_history的观测一致性）
3. **两阶段后训练**：先用(P_G, C_G)对做SFT（LoRA），再用GRPO做RLVR——奖励信号来自上述验证框架的加权复合分数（static 0.15, dynamics 0.25, semantics 0.3, information 0.3）

基座模型：Qwen2.5-3B-Instruct。对比基线：Base、SFT-only、RLVR-only、SFT+RLVR、GPT-4o。

## Experiment
在7个held-out博弈上评测（含OOD和不完全信息博弈）：
- SFT+GRPO综合最优（53.2%），显著超过Base（47.3%），但GPT-4o（66.7%）仍大幅领先
- SFT提升静态/模糊测试分数但不改善整体；RLVR改善语义遵从；两者结合效果最佳
- 完全信息博弈（如Gen. Tic-Tac-Toe）上SFT+RLVR接近GPT-4o；不完全信息博弈差距巨大
- 所有模型在语义层（Tier 3）表现较差（SFT+RLVR仅33.8%，GPT-4o仅33.6%），说明将自然语言规则转化为忠实代码实现是根本难点
- 3B模型无法生成正确的resample_history逻辑（Information得分多为0%），有时模型甚至主动注释说"太难了"而选择返回简化实现

## Value
- 创新度：2/5。SFT+RLVR的后训练范式本身不新，验证框架的分层设计有一定工程价值，但整体是已有技术（GRPO、LoRA、代码验证）在GameCWM这一特定场景的组合应用
- 相关度：0/3。本文的"世界模型"是博弈论意义上的可执行代码环境（实现棋牌/策略游戏规则的Python函数），与视频世界模型、3D世界模型、隐式世界模型（JEPA/Dreamer）在概念和技术路线上无实质关联。不涉及视觉感知、连续状态空间、潜变量学习等

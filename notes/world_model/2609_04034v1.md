# Editable Visual Design

## Insight

有一个工程层面的 insight。Observation 是：代码代理擅长真实文本、DOM 分层与精确布局，却缺少整体审美和复杂素材表达；端到端图像模型恰好相反，画面好看但文字易错、像素纠缠且难编辑。推论是将图像生成置于代码之前，只把它当构图参考和局部素材渲染器，再由 VLM 重建结构化页面，可以同时保留审美先验与可编辑性。论文用少量对照案例和 replay 展示这一互补性，没有受控实验，因此只能证明流程可行，不能证明其普遍优于既有分层设计系统。

## Motivation

论文解决自动视觉设计的交付矛盾：纯 coding agent 能产出 HTML/CSS/SVG 和可维护层级，但常出现大空白、模板化卡片和廉价素材；diffusion/image model 能提供构图、光影和纹理，却输出扁平 bitmap，文字与局部修改不可靠。作者认为实际海报、信息图不仅要“生成得像”，还要让设计师继续拖拽、改字、换图并导出分层资产。这是视觉设计代理的实际问题，但并非视频、3D或隐式世界模型问题；“visual world simulator”在文中只是对图像生成工具的比喻。

## Method

系统的 creative brain 使用 GPT-5.6 Sol 驱动的 Codex，visual simulator 使用 GPT Image 2。流程分五步：（1）解析 brief、尺寸、内容与风格，生成一张 imagined visual 供用户尽早确认方向；（2）VLM 从参考图读取配色、构图、层级和密度；（3）图像模型按需分别生成无文字背景、插画、icon 等孤立素材，支持时直接透明背景，否则用纯绿底再 matting；coding agent 按固定像素 canvas 写原生 HTML/CSS/SVG，把可移动元素分别标成 DOM layer；（4）headless browser 做越界、资源和 DOM 检查，VLM 看实际 screenshot 后针对性 patch，一般迭代一至两轮；（5）交付可双击文字、拖拽缩放、分层导出的 GUI，并序列化从规划、prompt、素材到修复的 Agent Design Replay。

方法没有训练新模型、学习世界动力学或定义新的优化目标，创新主要是“先想象、再编码”的工具编排和结构化交付约束。

## Experiment

论文采用案例展示而非量化实验。Figure 3 在两个 brief 上并排比较 GPT Image 2 的扁平图、纯 Codex 页面和本文组合：前者被标出乱码/不可编辑，后者被标出留白/布局问题，本文结果展示真实文字和分离图层。Figure 4 展示 City Atlas、Summer Music、Memphis Future 三类 prompt→coded result→editable canvas；Figure 5 给出两个 replay，其中信息密集案例含120层、13组并经 review 修复，旅行海报为6层、1组且首轮通过。另有活动海报、信息图、营销材料和长文本样例。

没有公开任务集、样本总数、运行次数、成功率、编辑耗时、layer correctness、审美人评或统计检验；没有去掉 imagined visual、独立资产或 self-healing 的消融，也没有与 COLE/OpenCOLE、AutoPresent、PPTAgent 等结构化生成系统做同协议比较。作者明确承认“cases rather than scores”，所以“production-grade”和“兼具精致审美”目前主要是视觉示例结论。

## Value

对设计代理而言，这是一套可复用的工程 recipe：生成模型提供难以代码化的视觉先验和素材，代码承担文字、约束与后续编辑，render feedback 负责闭环修复。对我们的世界模型研究价值很低：它没有时间演化、动作条件状态转移、latent dynamics、规划 rollout 或物理环境；可借鉴的仅是“昂贵慢思考提供低频先验、执行器高频纠错”的系统组织类比，不能据此讨论 world modeling。

## Strengths

最终交付物确实是可检查、可修改的原生结构，而非把位图包装成“可编辑”；参考图不直接进入成品，素材重新独立生成，降低图层纠缠；确定性 DOM 检查与截图审阅分工合理；Agent Design Replay 保留 prompt、素材、代码和修复轨迹，便于定位问题。论文也坦率承认审美和可编辑性难量化、能力受底座限制及多页一致性尚未验证。

## Weaknesses

证据几乎全是作者挑选和标注的成功案例，缺少盲评、真实设计师编辑任务和可复现统计，无法排除 cherry-picking；VLM 同时负责生成和审美审核，容易形成自我确认闭环。所谓基线并非统一预算、统一迭代次数下的严谨比较，且只展示两个主对照。绿幕抠图在主体含绿色、半透明、发丝或阴影时会失效；固定 canvas 易保证坐标，却未验证响应式、多页或跨格式保真。方法高度依赖专有 frontier 模型，底座版本变化会影响复现，论文也没有报告成本、时延或失败率。

## Future Work

作者指出需扩展到多页 deck 和完整网站，并在长输出中维持字体尺度、配色与视觉线索一致；需要比 VLM 代评更可靠的审美评价，以及真正反映设计师能否完成修改的 editability 测试；还提出让 AI 直接通过 GUI 鼠标在 canvas 上布局和绘制。工程上还应研究复杂透明素材的稳健分层、跨模型复现、成本/延迟和人工干预收益。

## Rating

创新度评分：2/5 - 图像先验、独立素材、代码交付与视觉自修复的组合实用，但没有新模型或严格评测，技术贡献偏工程编排。
相关度评分：0/3 (Noise) - 文中的“visual world simulator”只是静态图像生成工具，不涉及视频、3D或JEPA/Dreamer世界模型。

## TL;DR

图像模型先构图并生成分层素材，编码代理再交付可编辑网页；工程案例可看，世界模型方向可跳过。

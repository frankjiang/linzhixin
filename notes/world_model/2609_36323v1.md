# Towards an AI Software Factory for Data Systems

## Insight
作者观察到仅加速写代码会受软件生命周期其他环节限制，于是提出用贯穿选题、编码、评审和运维的证据记录形成持续优化循环。部署数据支持工程效率提升，但“World Model”在本文指存储代码、遥测与工作流的知识库，并非预测物理世界的学习模型。

## Motivation
数据系统的性能优化既要找对目标，也要验证真实负载收益；单一编程代理缺少跨阶段证据与反馈。论文聚焦有可自动度量目标的演化式编程任务，试图降低选题、搜索、验证和运维的人力瓶颈。这是软件工程问题，与用户研究方向没有实质交集。

## Method
“World Model”由原始工件存储、物化视图及按任务提供证据的接口组成；Hotspan 根据代码、遥测和评审记录选优化目标并构造基准；Darwin 以能自行编码、测试和反思的代理为变异算子，用假设记忆及搜索选择持续优化；自动评审和 AutoSRE 处理后续阶段。执行轨迹写回知识库，并将有分数的代码变异对用于 DPO 微调。整体是工程平台与多代理工作流，未建模视频、三维环境或隐式物理动态。

## Experiment
在 circle packing 上报告 Darwin 相对搜索基线最高约 22 倍 token 效率；45 个开源系统每项设 2500 美元推理预算，表现最好的 20 项平均性能增益 13.8%。微软内部数十仓库的性能优化工具估算应用阶段每工程师小时产出 0.35 个 PR，约为常规代理编码的 3 倍；另报告部分生产负载资源收益。偏好微调样例在同等 circle-packing 质量下减少 72.5% 变异代理调用。指标分属不同案例，缺少统一、随机化的端到端生命周期对照。

## Value
对软件代理平台或工程知识治理有参考性；对视频、3D、JEPA/Dreamer 世界模型无直接研究价值。

## Strengths
关注代码之外的选题、评审和运维；提供实际仓库及生产部署案例；把知识证据的来源、权限与更新流程写得具体。

## Weaknesses
“世界模型”只是领域知识库，名称易造成检索噪声。许多效果是案例或内部估算，缺少相同任务下的严格消融和独立复现；作者也承认优化目标的选择可能偏向适合方法的项目。若目标无法可靠自动测量，核心搜索循环不易迁移。

## Future Work
作者明确提出扩展通用知识库、自动构造生产负载仿真与语义正确性证明、实现更系统的线上影子验证、管理噪声/慢反馈的搜索成本、校准知识库更新的信任门槛，并探索从离线偏好到在线学习。

## Rating
创新度评分：2/5 - 大型工程工作流整合及部署证据有价值，但核心技术多是已有代理搜索、知识库和偏好微调的组合。
相关度评分：0/3 (Noise) - 文中“World Model”并非视频、3D 或隐式世界模型。

## TL;DR
构建以知识库、性能目标和代理搜索贯通软件开发的工厂，所谓世界模型并非物理预测模型，可跳过。

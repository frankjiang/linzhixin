# PatchWorld: Gradient-Free Optimization of Executable World Models

## Insight
文本智能体环境通常建模为POMDP，假设模拟器的隐含状态和转移动态对智能体不可见。本文探索：能否从离线轨迹中诱导出可执行的Python代码作为世界模型？核心方法：反例引导的代码修复(counterexample-guided code repair)——用LLM生成初始世界模型代码，再通过观测到的轨迹与模型预测的不一致作为反例，迭代修补代码逻辑。

## Motivation
- 问题：文本智能体如何在部分可观测环境中获得可解释、可执行、可检查的世界模型？
- 同行方法：黑盒神经网络世界模型（不可解释）、LLM直接推理（无状态跟踪）
- 优势：代码世界模型可检查、可重放、可局部修补

## Method
- **PatchWorld框架**：离线轨迹 → LLM生成初始belief-state程序 → 对比预测与实际观测 → 反例引导LLM修补代码 → 迭代直到一致
- 变体PatchWorld-Simple vs PatchWorld-Residual（带人工指定的残差记忆偏置）
- 梯度无关：修复过程不使用梯度，纯LLM代码生成+验证
- 7个AgentGym环境测试

## Experiment
- PatchWorld-Simple在live one-step lookahead达76.4% macro success，是所有code-based方法最高
- 发现有趣trade-off：PatchWorld-Residual改善观测保真度但削弱决策效用
- 分析：提升observation fidelity可能以牺牲action-discriminative dynamics为代价
- 预测模块本身不调用LLM（推理时零LLM调用）

## Value
提出了一种新颖的世界模型形式——可执行代码世界模型，与视频/3D/隐式世界模型是完全不同的路径。发现的observation fidelity vs decision utility trade-off有理论意义。但应用场景限于文本智能体，与视觉世界模型方向距离较远。

## Strengths
亮点是提出了一种新颖的世界模型形式——可执行代码世界模型，与视频/3D/隐式世界模型是完全不同的路径。

## Weaknesses
不足是变体PatchWorld-Simple vs PatchWorld-Residual（带人工指定的残差记忆偏置）

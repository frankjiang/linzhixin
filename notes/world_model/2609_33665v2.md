# CompoWorld: Compositional Environment Scaling for General Agents

## Insight
单个数字服务学得好，不代表代理能处理跨服务的数据依赖。作者推论：复用有状态服务并合成有因果依赖的工作流，比只增加单服务任务更有训练价值；1K 条 SFT 的匹配数据量实验中，组合环境在 AutomationBench 达 33.33%，单环境仅 12.83%。这是 LLM 工具代理的训练洞见，与视觉物理世界模型无关。

## Motivation
已有代理环境合成常局限单一应用，真实工作流则跨数据库、邮件、日历等系统传递信息。本文解决可执行环境扩展、跨服务任务验证和多条件任务奖励；问题对通用工具代理重要。

## Method
从 MCP 工具规格由编程代理生成 Pydantic 类型状态、工具实现与测试，独立测试不通过的工具隔离；少数难实现的工具由语言模型模拟状态更新和返回值。随机游走选服务并构造跨服务依赖图，任务代理生成初始状态、目标和可执行判定器，并亲自调用工具验证可达性。用验证成功轨迹做 SFT，再以 GRPO 训练：按同组轨迹中每项任务条件的失败频率加权部分奖励。所谓“世界模型”是模拟数字工具的语言模型，不是视频/3D/机器人动力学模型。

## Experiment
构建 448 个服务、10,130 个工具；3K 成功轨迹 SFT 加 1K 任务 RL 训练 Qwen3.6-35B-A3B。八个代理基准平均比原模型高 9.17 分；AutomationBench 完整成功率 10.33→32.33%，SkillsBench 32.52→47.71%。相同 1K SFT 预算下，组合环境在 AutomationBench 为 33.33%，单环境为 12.83%。RL 较 SFT 八基准平均仅 +1.2 分，τ³-Banking 甚至小幅下降；奖励重加权的训练评估曲线末期约 0.76 vs 不重加权 0.67。附录称 7.1% 工具、约 10% 样本使用语言模型模拟；并无系统的模拟器真实性评测。

## Value
对研究视频、3D 或 JEPA/Dreamer 世界模型几乎无直接借鉴；可单独参考其“可验证任务组合”的代理训练设计。

## Strengths
类型化状态和可执行终态检查使任务可验证；与单服务同数据预算对照；诚实说明主要增益来自 SFT，模拟工具只覆盖少数情况。

## Weaknesses
合成服务和测试由代理生成，真实业务规则与边界情况覆盖有限；只对部分环境人工抽查，下游成绩不能证明每个状态转移准确。组合服务规模的组合数只是候选空间，不等于可解且有意义任务数。RL 收益不稳定。

## Future Work
作者指出需提高编程代理生成/验证服务的质量，并选择兼容服务、构造实质跨服务依赖；未提出与视觉物理世界模型相关的后续方向。

## Rating
创新度评分：1/5 - 对目标研究方向没有新的世界模型技术；贡献主要是数字工具代理的环境与训练管线。
相关度评分：0/3 (Noise) - 仅以语言模型模拟部分软件工具状态，与视频、3D、隐式物理世界模型无实质关联。

## TL;DR
组合可执行数字服务生成跨应用任务并训练工具代理，所谓世界模型只模拟少量工具调用；本方向可跳过。

# Tycho: Active Abstraction with Programmatic World Models for ARC-AGI-3

## Insight
论文观察到 ARC-AGI-3 中每个探索动作既提供规则证据又消耗得分预算，因此世界模型的构建、验证和调用本身具有 opportunity cost。实验出现关键反例：verification failure 后自动修复的 Trigger policy 得到更准确的历史 transition match，却只达 83.07 RHAE，低于由 actor 自主请求 builder 的 Orchestrator（88.49）。由此推论，transition fidelity 只回答“模拟器是否复现已见动力学”，不能保证目标识别正确、离轨泛化可靠或咨询模型能改善下一动作；是否、何时以及如何建模也是控制问题，作者称为 active abstraction。

## Motivation
ARC-AGI-3 不给动作语义、规则或目标，agent 必须从昂贵的在线交互中推断 hidden state、跨 level 规则和终止条件。纯 LLM reasoning 容易忘记历史或导入错误游戏先验；强制维护完整模型又可能浪费推理并放大错误。问题在 agent adaptation 与 symbolic model-based planning 上重要，但环境是离散彩色网格，和视频/3D/JEPA 世界模型只有高层方法论联系。

## Method
作者将游戏形式化为带渲染、action mask、transition emission 和 terminal outcome 的 deterministic Moore machine。历史中 decision frame、动画 transient、level completion、game over、reset 和 next-level initialization 被严格分型，避免把 agent 无法行动的帧误当 transition 起点。相同画面可能对应不同 hidden state，因此模型需保存计数器、选择工具、相机偏移等历史变量；renderer 可以对未知像素返回 \(\bot\) 或有限 observation variants，verification 同时报告 accuracy 与 coverage。

可执行 world model 是自由 Python hypothesis，必须实现 `init_state`、`transition`、`render`、`outcome`，可选 heuristic、candidate action、state key 或自定义 planner。模型从 level 初帧初始化，跨 level 共享机制；verification 回放真实交互并单独检查 ordinary transition 与 terminal outcome；planner 从 threaded hidden state 搜索到 `level_complete` 的路线，以每步预测帧 hash 守护建议，实际 actor 仍逐步观察后提交动作。

四种 policy 共用同一 evidence/workspace：No Model 仅直接 reasoning；Single 由 actor 自己编辑；Orchestrator 由 actor 按需调用 builder；Trigger 在验证失败和生命周期事件后自动调用 builder。核心贡献不是某种新动力学网络，而是把 free-form program hypothesis、部分预测、验证、规划与 model-use metareasoning 做成统一 agent workbench。

## Experiment
在全部 25 个公开 ARC-AGI-3 game、183 level 上，先用 Opus 4.8、相同 3,500 call/game 与预算各运行一次四 policy：No Model、Single、Orchestrator、Trigger 的 RHAE 分别为 79.07、85.36、88.49、83.07，完成 game 数为 19/19/21/18，level 数为 157/162/166/162。Orchestrator 在与 No Model 共同完成的 157 level 上少用 18.9% 动作。Trigger 的转移模型更准确、调用 builder 更多，却完成更少，支持“模型准确性≠策略价值”。

按同一公开集选出 Orchestrator 后再换 frontier model：GPT-5.6 Sol 和 Opus 5 都达到封顶 100 RHAE、完成全部 183 level，分别使用 7,766 和 6,641 个 scored action；Opus 5 比 GPT 少 14.5%，且较聚合官方人类基线少 61% 环境动作。论文还报告 game-level bootstrap/leave-one-out、human replay midrank、模型执行率、transition match、coverage、terminal recall/false-positive、plan-following 与推理成本，并用多个 trace 展示跨 level 规则复用、可辨识 probe 和模型修复。

证据的重大限制是每配置只有一次 stochastic run，5/25 game 用于 harness 开发，policy selection 与 frontier evaluation 都在同一公开集上；100 分只说明该公开 testbed 的系统表现，不能证明 unseen generalization。环境动作也不计高昂内部推理：Opus 5 使用约 15.1K model call、估算 $2.99K，论文估计能耗仍远高于人类。

## Value
对世界模型研究最有价值的启发是把 model utility 与 predictive accuracy 分开，并测量 model construction/verification 的成本、coverage、outcome accuracy 和 advice usage。部分模型和 guarded plan 也提醒我们：世界模型未必需要重建所有像素，只需在候选路线周围保持 action-relevant equivalence。不过该工作高度依赖 LLM 写 Python、离散精确环境和 benchmark-specific harness，无法直接迁移为视频或 3D world model 方法。

## Strengths
- 对 decision/transient/terminal evidence 做严格分型，避免常见评测和回放错误。
- 自由程序状态允许按游戏选择网格、对象、计数器、UI 模式等表示，不强加单一 ontology。
- 将 transition、render、outcome、coverage、planning 与行动成本分开测量，诊断维度丰富。
- 用 matched policy comparison 直接展示选择性建模优于强制建模，并公开 trace/scorecard。
- 局限讨论坦诚，明确区分公开集系统成绩、unseen generalization、环境动作效率和总推理成本。

## Weaknesses
- 每个配置只跑一次，无法估计 LLM agent 的 run-to-run 方差；game bootstrap 不能替代重复生成。
- 五个公开 game 参与 harness 开发，全部 25 个又用于 policy selection 和最终评估，没有真正 held-out game。
- 三个 game 在模型 cutoff 前已公开，Opus 5 cutoff 甚至晚于完整公开集，训练污染不能排除。
- Orchestrator 的收益同时混合 builder delegation、更多可用推理、模型所有权和 allocation 差异，不能归因于单一 world-model 组件。
- 100 RHAE 大量受 score cap 饱和，且忽略 15.1K 次调用、数千美元推理和很高 latency。
- Python 模型适合离散算法环境，但在连续、随机、部分可观测的视觉物理世界中会更脆弱且难以精确验证。
- ARC 特定的 64×64/16 色、RESET、跨 level、HUD 类别和人类可解先验限制通用性。
- 外层 agent/harness adaptation 仍由作者筛选、实现和验证，不是自主 self-improvement。

## Future Work
作者明确把冻结 harness 在未见 ARC game、独立环境及其他交互域上的测试列为首要方向，并建议重复运行、跨 frontier/open-weight model 比较、显式不确定性、更好的 reasoning/model-construction allocation、验证计划的安全复用和降低推理成本。更长期目标是让 agent 自己从跨 run 反馈提出、实现和独立验证 harness 修改，闭合外层 adaptation loop。

## Rating
创新度评分：3/5 - active abstraction、部分可执行模型与 model-use metareasoning 的系统化整合有新意，公开集效果强；但主要是 agent harness 和评测研究，缺乏未见任务与重复运行验证。

相关度评分：1/3 (Tangential) - 世界模型的验证、规划与使用决策具有间接启发，但对象是 ARC 程序模型，不涉及视频、3D 或 JEPA/Dreamer 式隐式表征学习。

## TL;DR
以可验证 Python 世界模型和按需建模提升 ARC 交互效率，系统启发强但偏离主线，可选读。

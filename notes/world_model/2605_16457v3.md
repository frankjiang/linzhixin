# Identifiable Token Correspondence for World Models

## Insight
Observation：Token-based transformer世界模型在长程rollout中出现物体复制、消失、变异等时序不一致问题。根本原因：现有方法将next-frame prediction纯粹当作token生成问题，transformer并行输出所有位置的token，无法建模"哪些token应该从上一帧保留"。

推论：视觉环境中相邻帧大部分内容相同（如游戏中tile只移动不消失），若在解码时显式建模token的跨帧对应关系（来自上帧 vs. 新生成），可大幅减少幻觉。

验证：引入Optimal Transport作为解码步骤，将next-state token assignment建模为结构化的分配问题，在不改变transformer训练的情况下显著提升长程预测准确率和下游RL性能。

## Motivation
Token-based world model（IRIS、Δ-IRIS、Dedieu et al. 2025等）已是visual RL的主流范式，但temporal inconsistency是关键limitation：
- 物体复制：同一实体出现在多个位置
- 物体消失：实体在rollout中突然消失
- 物体变异：一个实体变成另一个

这些错误在imagination rollout中compound，严重影响策略训练质量。核心问题是：token预测缺乏身份persistence的归纳偏置。

## Method
ITC是一个**解码步骤**，插入在transformer预测和最终next-state token之间，不改变transformer架构和训练：

1. Transformer照常输出candidate next-state tokens $\tilde{s}_{t+1}$
2. 构建二部图：源节点 = 上帧tokens $s_t$ + candidate tokens $\tilde{s}_{t+1}$，目标节点 = 最终tokens $\hat{s}_{t+1}$
3. 定义affinity矩阵：
   - $A^{(prev)}_{ij}$：上帧token $i$ 与目标位置 $j$ 的相似度 - 距离惩罚$c_d \cdot D((x_i,y_i),(x_j,y_j))$
   - $A^{(gen)}_{kj}$：新生成token $k$ 用于位置 $j$ 的bonus减去wildcard penalty $c_w$
4. 用Sinkhorn算法求解最优传输计划，再二值化为硬分配
5. 最终解码：若分配到prev→直接复制上帧token；若分配到gen→从transformer预测采样

关键特性：
- 即插即用，不改变transformer训练
- 兼容patch-lookup和VQ-VAE两种tokenizer
- 用3D RoPE编码时空位置信息

## Experiment
在4个benchmark上达到SOTA：
- **Craftax-classic**：Return 72.5% / Score 35.6%，显著超越previous best 67.4%/27.9%（Dedieu et al.），收敛更快
- **Craftax**：Return 7.09% / Score 2.40%，超越Dedieu 5.44%和Simulus 6.59%
- **MinAtar**（4个Atari游戏）：全部超越baseline
- **Atari 100K**（26个游戏）：IQM 1.092 / Optimality Gap 0.376，超越Simulus (0.990/0.412)

消融分析：
- Per-step预测准确率：46.94% → 51.13%（overall），含creature的难样本提升更大
- 运行时间开销仅+2.8%（8.08→8.19 min/epoch训练，4.48→4.78 min imagination）
- 对超参数$c_d$和$c_w$不敏感

定性分析（Fig 4-5）：明确消除了baseline中的物体复制和消失问题，DreamerV3中也存在类似问题。

## Value
这是一个简洁有效的贡献：
1. 问题定义清晰——token identity persistence是world model的基本需求
2. 方法优雅——OT是解决assignment问题的自然工具，且不改变训练
3. 效果显著——ICML 2026接收，4个benchmark全SOTA
4. 计算开销极低（+2.8%）

启发：(1) 世界模型不仅需要预测"内容"还需要建模"身份对应"——object permanence作为归纳偏置；(2) OT是连接帧间token的好工具；(3) 解码阶段的结构化后处理是被低估的改进方向。

待解决：连续latent空间（如Dreamer）中如何类似地建模对应关系？3D场景中的应用？

# Recursive Code World Models: Building Complex Worlds through Recursive Scene Programs

## Insight
全图编辑容易遗漏小结构，独立局部编辑又会破坏接触、遮挡和布局。因此每个子场景都应经历“建立整体→递归构建局部→返回整体修复”，而非只拆分一次。相同局部视觉访问条件下的流程消融提供初步支持，尚不能排除计算量差异。

## Motivation
代码可表达可编辑 3D 世界，但表达能力本身不决定复杂场景如何被可靠构建。VIGA、SEIG 等已有渲染反馈或分阶段编辑；本文试图改善跨尺度细节与全局一致性的组织方式。

## Method
- Recursive Scene Program 将几何、材质、放置规则、共享依赖与子程序引用组织成可执行 Three.js 场景。
- 冻结视觉编码 agent；每次递归调用保有局部代码、参考图、匹配相机和剩余预算，在固定父场景快照中渲染、比较、编辑。
- 子任务裁剪参考图，同时裁剪相机视锥，保持外参，更新内参为 `K'=HK`，使各层局部观察共享投影关系。
- 返回父层后检查组装结果并修复跨组件关系；共享错误由拥有该依赖的祖先处理，相机修改由根节点负责。按视觉判断继续或停止，运行器最多允许五层。
- 创新集中在递归求解与上下文管理；没有训练新模型，也没有学习世界动力学。

## Experiment
- 五个整体参考、五个局部裁剪；同一 gpt-6-astra/high 骨干，对比 SEIG、VIGA、img2threejs。指标为 PSNR、SSIM、Canny Edge F1、LPIPS、CLIP；消融增加八个固定局部窗口 SSIM。
- 表 1：全部十图 PSNR、LPIPS 最佳，九图 SSIM 最佳。city-full 对 img2threejs：PSNR 18.2 对 15.5，LPIPS 0.158 对 0.243；valley-village 的 SSIM 0.38 低于 VIGA 的 0.41。
- 表 2 两场景、每设置一次运行：medieval-village 自由深度相对固定两层，PSNR 16.8→19.0、局部 SSIM 0.52→0.60；school-block 无相同趋势，自由深度局部 SSIM 0.52，固定两层 0.57。
- 图 10 展示额外视角，图 11 展示真实递归调用树；局部裁剪场景从背面看仍存在未建区域，不能视作完整世界恢复。

## Value
为可编辑 3D 世界提供一种推理时分配计算的方法：局部拥有完整求解过程，组合后必须重新检查相互关系。对代码式 3D 构建有用，对视频预测或隐状态动力学仅有间接启发。

## Strengths
- 相机继承与父层复查机制具体，可迁移到其他分层重建流程。
- 输出可执行、可编辑程序；提供提示词、调用树和方法内流程对照。

## Weaknesses
- 仅十个参考图，其中多个裁剪共享同一来源；单模型、单次运行，消融仅两场景。
- 虽统一骨干和视觉工具，未报告可核验的 token、时间或费用预算匹配；不能把所有提升归因于递归。
- 主要测参考视角图像相似性，缺少真实多视角几何、物理关系及编辑成功率评测；单图背面与尺度仍不确定。
- 依赖 agent 视觉判断，无收敛保证；复杂案例调用次数高。

## Future Work
作者建议扩大基准、重复运行，并通过人工评价空间关系，以更充分评估重建可靠性。

## Rating
创新度评分：3/5 - 将递归完整求解、投影继承与组合复查系统化，具有方法价值，但仍是现有编码 agent 的推理流程设计。
相关度评分：3/3 (Core) - 直接研究可执行 3D 世界构建；属于静态代码场景重建，不是动态预测模型。

## TL;DR
以全局—局部—全局递归构建可编辑三维场景，改善细节与组合关系，但计算公平性证据不足，可选读。

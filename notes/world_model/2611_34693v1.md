# ShowNow: Fine-Grained Speculative Streaming for Responsive World Models

## Insight
观察：单次生成三帧潜变量使用户动作最多等一个较长更新周期；提前生成多个动作分支虽耗算力，但可在下一显示截止前直接选择。推论：响应延迟由潜变量粒度、候选覆盖、输入相位和播放队列共同决定；仅比较生成耗时会误判交互体验。论文建立“预备→选择→提交”时序窗口，并用同模型配对输入/队列实验验证：准备的候选在截止前 6–40 ms 到达的动作上更易按时显示，但默认一帧缓冲时中位显示延迟几乎相同。

## Motivation
流式视频世界模型需在连续播放中响应新动作。已有加速多关注采样步数/吞吐，较粗时间块与动作变化后的重新生成仍造成尾延迟；预生成所有未来又浪费算力和显存。可交互模型需要具体的端到端动作到显示指标与资源约束。

## Method
从相同 ViZDoom 状态采集八种动作的匹配分叉视频（10,241 个保持动作、11,471 个切换动作）；在 SolarWM/Wan2.2 底座上训练树形注意力：所有分支共享已提交历史，各未来仅看自己的历史，配合共享噪声的分支流匹配。经 AnyFlow 蒸馏和自生成历史微调得到每次生成一个潜变量（四帧）、三步去噪的学生。运行时预备最多八个动作未来，用户输入选择一个并将其写回公共历史；共享前缀 KV 缓存、分区注意力、融合提交与播放队列提高效率。创新主要是多未来训练与流式调度/注意力实现的系统组合。

## Experiment
单 H100、16 fps、1857 次输入的六种子连续流：原三潜变量 SolarWM-FT 的显示 P50/P90/P99 为 620/983/1385 ms；ShowNow 八候选为 208/345/374 ms、15.99 fps。但在相同一潜变量模型和默认一帧缓冲下，Reactive 为 211/344/373 ms，八候选 208/345/374 ms，主要收益是重启空帧由 1.56% 降至 0.09% 及提交延迟 136→88 ms。32 fps 压力测试的零帧缓冲中，四候选 P50/P90/P99 为 73/137/153 ms，Reactive 为 119/199/216 ms。共享历史八分支生成 271.6 ms、17.1 GiB，独立 batch 为 301.8 ms、32.8 GiB。动作切换前 0.5 秒识别率 0.813（粗粒度基线 0.591），但稳定段准确率 0.901（基线 0.969）、1 秒 PSNR 17.64（基线 18.80），一分钟生成 FD 11.4，显示保真/长时一致性代价。33B 案例的解码在独立第九张 GPU 上建模，不能等同单卡实测。

## Value
对交互式视频世界模型的启发是把输入到提交、输入到显示、空帧、尾延迟与动作准确性分开报告，并按目标帧截止时间设计预生成覆盖；默认队列可能掩盖候选准备的实际收益。适合设计低延迟推理系统与评测协议。

## Strengths
同一学生模型上的 Reactive/One/Eight 候选配对比较较清楚；公开播放相位与队列阈值的影响、内存/算力成本以及保真退化；有完整连续流和动作切换测试。

## Weaknesses
核心八动作实验依赖 ViZDoom 固定离散动作，候选数随动作空间扩大难扩展；流式分支增加 GPU 占用（约 80%），默认一帧缓冲下显示延迟几乎不变；细粒度生成降低稳定动作准确率和图像质量，33B 延迟含独立解码 GPU 的模型化假设。

## Future Work
作者强调需权衡细粒度自回归的保真与长时一致性；可进一步研究连续/大动作空间下的候选选择，以及适配实际网络与显示设备的调度。

## Rating
创新度评分：3/5 - 树形共享历史与投机调度集成扎实，但核心加速组件多为现有技术，收益依赖播放条件。
相关度评分：3/3 (Core) - 直接研究可交互视频世界模型的训练、推理与响应评测。

## TL;DR
用单潜变量更新与共享历史的多动作预生成改善流式世界模型响应和空帧率，但牺牲部分保真；值得精读。

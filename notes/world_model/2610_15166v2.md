# ExeWorldBench: Benchmarking Code-Based Executable 3D World Modeling

## Insight
能运行的 Blender 程序和好看的 3D 结构，不意味着模型理解了机械因果。作者把单机构、跨机构因果链及只给目标的合成逐级测试；修复语法错误后代码运行率大升，机械与因果得分仍低，执行链越长退化越明显，说明评测必须核验动作由正确物理连接产生。

## Motivation
已有物理问答、静态 3D 代码生成和简单运动基准各测一部分能力，却难判断模型能否从视觉或高层目标构造真正可执行的 3D 世界。该问题对 3D 世界模型的因果与可交互评估有直接意义，尤其可以避免只用渲染相似度评判世界模型。

## Method
ExeWorldBench 三任务：T1 从单图写 Blender 程序重建单个机械机构及完整运动；T2 用 4–13 个原子机械组件形成多阶段空间/因果链；T3 从文本条件合成，分别给定组件集合或只给目标、状态、事件与物理依赖。T1 数据来自机械动画并做静图运动可推断性筛选；T2/T3 用组件代码库、模型生成和人工审核构建。用代码运行率、视觉结构 V、单机构运动 M、阶段间可执行因果机制 ECM、初始/中间/最终目标满足率 G 分别评分。对 API 输出另用编码代理仅修执行错误，以区分语法问题和机制问题。

## Experiment
比较编码代理和多个 API 模型，以 Opus 5.5 按生成视频/条件打分。T1 中 GPT-6 Astra 编码代理运行率 100%、V=7.16/10、M=6.32/10；普通 API 版本修复后运行率 94%，M=5.08。T2 编码代理的 ECM=5.25，而多数 API 模型修复后仍接近 0；T3 只给目标时编码代理 ECM=5.82、目标满足率 90.14%，普通 API 版本修复后分别为 2.55 和 41.07%。T2/T3-1 的 ECM 随阶段数增加而下降；加入运动参考帧总体收益有限。

## Value
对 3D 世界模型评测值得精读：应分开代码可运行性、空间装配、机制运动、阶段因果传递和最终目标，并加入长时执行分析。可将这些指标移植到视频或可交互 3D 模型的物理一致性评测。

## Strengths
从结构证据到意图合成的难度梯度清晰；将中间因果传递与终态正确性分开，能揭示“动画凑结果”与真实机制执行的差别；附录给出条件化于成功运行案例的分数，避免运行率完全掩盖建模能力。

## Weaknesses
V/M/ECM/G 主要由单一 VLM 裁判评定，缺少与独立物理状态日志或人工评分的一致性验证；任务生成、参考构建和执行修复也使用强模型，存在同源偏差。代理与 API 的运行环境、工具和修复机会不一致，比较更适合看系统配置而非裸模型能力；机械组件库的覆盖面有限。

## Future Work
作者希望推动可将物理理解、可执行实现与长期因果链结合的模型；具体算法路线未提出。更强的客观物理判定器和跨组件类型扩展是从结果可推得的后续需求。

## Rating
创新度评分：3/5 - 提出层级化的可执行 3D 因果评测，指标设计有价值，但主要是基准构建而非新模型。
相关度评分：3/3 (Core) - 直接评测 3D 世界模型的机制、因果与可执行性。

## TL;DR
基准把可执行 3D 世界拆成结构、机械运动、因果传递和目标达成，揭示高运行率不等于物理正确；值得精读。

# Environment-free Synthetic Data Generation for API-Calling Agents

## Insight
有但偏数字环境。Observation 是 API-calling agent 训练需要大量状态化交互轨迹，而构建真实 API 环境和后端数据库很贵。推论是 LLM 可以临时充当“数字 world model”，根据 API spec、任务和交互历史生成一致的 API response，从而不需要真实环境也能合成轨迹。

## Motivation
解决 agentic trajectory 数据生成瓶颈。同行常依赖可执行 API sandbox，或用弱状态的一次性 LLM simulator。ESAT 目标是仅从 API specification 生成任务、状态化 API 交互轨迹和过滤后的训练数据。与物理/视频世界模型无关，但对数字 agent 世界模型有参考。

## Method
ESAT 三阶段：任务合成，用 bucketized generation 和 inverse-frequency sampling 保证 app/API 覆盖，再经 judge 和 rewriting；轨迹合成，teacher agent 调 API，LLM simulator 根据 API spec、参数、任务、同 app 历史、虚拟用户和时间生成 response，并做参数/schema/语义一致性检查；轨迹过滤，多次 LLM judge 保留正确、完整、非冗余轨迹。支持 read/write API 和跨 turn state consistency。

## Experiment
AppWorld：用 52 个合成 app 的 1,017 API 生成 6K 轨迹，用 AppWorld 7 app 生成 9K 轨迹。Qwen3.5-9B 在 Test-N/Test-C 从 25.2/15.4 提升到 75.7/65.7；多数组合超过真实 AppWorld training trajectories AWT。OfficeBench：20 API 生成 1.7K 轨迹，Qwen3.5-2B 从 9.1/0.7 到 69.6/40.9，多个小模型超过 GPT-4o/Nemotron baseline。模拟器质量：27K API calls 中 GPT-5.1 judge 认为 93.7% response 有效；长输出失败率升高。

## Value
对我们低相关，但有一个值得借鉴的观点：当真实环境不可得时，可以用“状态一致的 simulator + judge + filtering”先构建可训练交互数据。这个思路可能迁移到 embodied/world-model 数据合成，但本文没有物理 grounding。

## Strengths
pipeline 完整，覆盖任务生成、状态模拟、schema 校验和轨迹过滤；在 AppWorld/OfficeBench 上下游效果强；支持 write API，比简单 tool-call 数据更接近环境交互。

## Weaknesses
模拟器本身是 LLM，可能引入不可见幻觉和偏差；质量主要靠 LLM judge；不处理真实物理、视觉、3D 或 action dynamics；合成数据是否教会真实 API 失败模式仍不确定。

## Future Work
作者没有展开太多未来路线；自然方向是更强 simulator、人类或程序化验证、更多真实 API 迁移和长期状态一致性评估。

## Rating
创新度评分：3/5 - 无环境 API 轨迹合成和状态化 simulator 设计有效，但技术核心仍是 LLM prompting/filtering。
相关度评分：1/3 (Tangential) - 数字 API 环境的 world model，对视频/3D/JEPA/Dreamer 仅有间接启发。

## TL;DR
ESAT用状态一致的LLM API模拟器无环境合成agent轨迹，数字环境有参考，物理世界模型可选读。

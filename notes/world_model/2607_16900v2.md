# Environment-free Synthetic Data Generation for API-Calling Agents

## Insight
论文的 insight 是把 LLM 当作 stateful API simulator，也就是“数字 world model”：在没有真实 backend/database/API execution 的情况下，仅凭 API spec、任务、调用参数和历史响应，动态生成一致的 API 返回值。这个 world model 概念是软件/API 环境模拟，不是视频、3D 或物理隐式世界模型。

## Motivation
API-calling agent 训练需要多步轨迹，包括 read/write API 调用、环境反馈和最终回答。已有合成数据方法通常依赖可执行环境和预填充数据库，迁移到新 API 时工程成本高。本文解决的是：是否能只用 API 规格说明就生成高质量 agent trajectory，从而绕过真实环境构建瓶颈。

## Method
ESAT 分三步。第一步 task synthesis：按 difficulty、action type、task focus、app 数、API 数等 bucket 生成任务，使用 inverse-frequency sampling 覆盖低频 app/API，再用 LLM judge 过滤并重写成自然用户请求。第二步 trajectory synthesis：teacher LLM agent 逐步调用 API，LLM simulator 根据 API spec、输入参数、任务、同 app 历史、用户 profile 和当前时间生成 JSON 响应；系统还做 deterministic input validation、schema validation、semantic judge 和 retry loop，维护 per-task/per-app history 以保持状态一致。第三步 trajectory filtering：LLM judge 按任务完成度、参数 grounding、迭代、冗余等标准保留高质量轨迹。作者还合成了 52 个 synthetic apps、1017 个 APIs，作为 AppWorld 外的数据来源。

## Experiment
AppWorld 中，ESAT-AW7 使用 7 个 AppWorld apps 的 340 APIs 生成 9K 轨迹；ESAT-S52 使用 52 个合成 apps 生成 6K 轨迹。多个 Qwen3/Qwen3.5 模型经 SFT 后在 Test-N/Test-C 大幅提升；例如 Qwen3-8B 从 21.1/7.8 提到 ESAT-S52-AW7 的 64.9/49.1，Qwen3.5-9B 从 25.2/15.4 提到 75.7/65.7。ESAT 数据通常优于真实 AppWorld train trajectories (AWT)，且与 AWT 组合对 Qwen3 继续增益。OfficeBench 中 ESAT-OB 1.7K 轨迹让 Qwen3.5-2B 从 9.1/0.7 提到 69.6/40.9，Qwen3.5-9B 到 83.6/63.2。LLM judge 与真实 AppWorld verifier 的 precision 为 95.2%，与人工标注一致率 95%、Cohen kappa 0.90。模拟器质量分析中 GPT-5.1 judge 认为 93.7% API responses 有效；输出越长失败率越高，2K tokens 以上约 23%。

## Value
对 API-agent 数据合成很有价值，但对用户关注的视频世界模型、3D 世界模型、JEPA/Dreamer 类隐式物理模型几乎没有直接参考。唯一可借鉴的是“只用规格说明构建可交互环境反馈”的思想，可能类比到仿真器/环境模型自动生成，但本文没有处理感知、物理、空间一致性或可执行运动。

## Strengths
pipeline 完整，任务生成、模拟、过滤和 synthetic app 扩展都可规模化；支持 state-changing write APIs，比简单 tool-call mock 更强；对 simulator schema/semantic consistency 做了多层验证；下游 SFT 效果和 judge 质量都有较系统消融。

## Weaknesses
核心假设依赖 LLM 对 API 数据状态的文本一致性建模，长输出失败率明显上升。评估和过滤大量依赖 LLM-as-judge，仍有潜在 bias 和数据泄漏风险。它模拟的是软件状态，不涉及真实动态系统；“world model”命名容易与物理/视频世界模型混淆。对我们的研究方向基本不可用。

## Future Work
作者没有展开明确未来方向。自然改进包括使用更强 simulator 降低长响应失败率、减少 LLM judge 偏差、改进 state consistency 验证，并扩展到更复杂的真实 API/domain schema。

## Rating
创新度评分：2/5 - 在 API-agent 合成数据方向有工程价值，但从视频/3D/隐式世界模型视角看技术贡献相关性很弱。
相关度评分：0/3 (Noise) - 只是文本/API 环境模拟，不研究视频、3D、物理或 Dreamer/JEPA 类世界模型。

## TL;DR
把LLM当API环境模拟器合成工具调用轨迹，非物理世界模型，可跳过。

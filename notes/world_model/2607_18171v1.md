# FlashRT: Agent Harness for Guiding Agents to Deploy Real-Time Multimodal Applications

## Insight
有。Observation 是实时多模态应用的瓶颈常来自部署形态而非单个模型：节点放在哪张卡、是否流式、是否流水线并行，会强烈改变端到端延迟。论文的推论是让 coding agent 先把应用转成带状态读写和阻塞/流式边的图 IR，再在真实 workload 下搜索部署变体，比固定 serving 策略更适合应用级优化。证明主要是系统实验：同一应用在不同 agent 生成部署下出现数量级延迟差异。

## Motivation
解决实时语音/视频/世界模型应用的部署编排问题。现有 serving 系统通常面向单模型或固定 pipeline，编译器又难覆盖应用级状态、流式依赖和多 GPU 放置。这个问题对视频世界模型产品化关键，但不是模型学习算法问题。

## Method
FlashRT 是 agent harness。流程：参考实现 -> agent 生成 hierarchical graph IR -> IR interpreter 校验节点状态与依赖 -> agent 根据可并行/可流式机会生成候选部署 -> 应用测试 harness 验证正确性并 benchmark -> 维护候选队列直到没有可行变体。关键细节是把 persistent state read/write 和 blocking/streaming edge 显式写进 IR，使 agent 优化有可验证结构。

## Experiment
用 Claude Code/Opus 4.8，在 NVIDIA B200 和 AMD MI355X 上评测 5 类应用。面对面语音 agent 从顺序 107.92s 降到 3GPU 1.57s，8GPU 方案达 173.67 FPS；Qwen3-Omni 延迟 0.323s，优于 vLLM-Omni 0.433s；视频背景编辑从 1715ms/6.82FPS 到约 491ms/17.18FPS；WorldPlay 视频世界模型从 869ms/20.4FPS 到 2GPU 493ms/25.5FPS 或 625ms/31FPS；LongLive 也有类似收益。AMD 上也复现部署族收益。

## Value
对我们有启发的是：视频世界模型不只要训练好，还要把状态、流式输出和多模型 pipeline 当成一等对象做系统优化。它适合系统侧参考，不能提供 world model 表征或规划算法启发。

## Strengths
把 coding agent 的探索空间结构化，避免纯 prompt 式乱改；验证循环贴近真实应用；覆盖语音、视频和世界模型应用，系统收益明确。

## Weaknesses
主要贡献是工程 harness，依赖强模型 agent 和应用测试集；没有形式化最优性，也没有讨论 agent 失败边界、成本和多租户场景；对世界模型本体无算法贡献。

## Future Work
作者提到尚未纳入 LLM kernel 优化 agent，也只测试了一种 agent 配置；未来可扩展到更底层算子优化和更多 agent/search 策略。

## Rating
创新度评分：3/5 - 把 graph IR、验证循环和 coding agent 用于实时多模态部署有工程创新，但不是新世界模型范式。
相关度评分：2/3 (Related) - 服务视频世界模型和实时多模态应用，系统借鉴价值直接，但不研究模型学习。

## TL;DR
FlashRT用IR和验证循环让coding agent自动优化实时多模态/视频世界模型部署，系统侧可选读。

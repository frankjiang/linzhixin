# WorldPager: Zero-Stall Tiered Memory for Long-Horizon World Models on a Single Consumer GPU

## Insight
观察：交互式视频世界模型每块计算约 1.2 秒，而需取回的少量历史 KV 可在这段时间由 NVMe 预取；访问集合由相机位姿近似预知。推论：其记忆瓶颈首先是容量和位置编码上限，而非带宽。作者用一阶容量/带宽模型及保留配置验证溢出点（8/8 在一块内）和是否停顿（15/15 正确），再以单卡长时运行验证方案。

## Motivation
场景重访需要历史 KV，但 Matrix-Game 2.0 在 RTX 4090 上 GPU bf16 KV 到第 21 块、32 GiB 内存到第 60 块，int4 DRAM 到第 226 块；原 RoPE 位置表在第 341 块停止。纯量化只延迟耗尽，按需读取产生等待。对长时交互式视频世界模型，这是直接的部署障碍。

## Method
不改检索策略，把历史 KV 按层/块做 KIVI 式对称 int4 压缩，存于 GPU 暂存槽、固定页主存、NVMe 三级；历史块约从 486.6 MB 降至 129.4 MB。当前块去噪时按匀速外推位姿预测下一块要取的 3 个历史块并异步预取；错过则复用上一块集合，绝不因缺页等待。脏块后台写回，O_DIRECT 避开页缓存。越过原位置上限后扩展表并对检索到的 key 重新旋转至当前窗口附近；原前 341 块保持逐比特一致。核心是面向世界模型访问规律的系统组合。

## Experiment
RTX 4090、32 GiB 主存、单 NVMe，对 MG2 的滑窗、GPU KV、DRAM bf16/int4、按需读取、后台预取等重实现基线比较；指标为每块耗时、停顿、内存、LPIPS 重访一致性和 MUSIQ 质量。3000 块/37.5 分钟视频连续生成，主存峰值 30.7 GiB，334 GiB 写入 NVMe，无超过 0.5 ms 的定义内停顿；生成耗时 63.2 分钟，约 9.5 fps。按需 NVMe 读取约 60 ms/块，预取中位 0；长间隔重访 int4 的 MUSIQ 约低 1.28 分。封存短程测试集上未见显著质量损失；LingBot-World 只验证系统吞吐，因其原模型检索本身未改善重访质量。

## Value
为相机可控视频世界模型提供容量规划与运行时记忆设计模板；尤其提醒评测“无等待”与画质、重访一致性要分开。值得精读系统测量和回退语义，模型研究可选读具体实现。

## Strengths
定量定位容量墙/位置墙，事先登记部分预测并实测；同时报告长程写入、重访读取和画质；清楚区分 int4 的已有技术与自身系统贡献。

## Weaknesses
无等待通过复用过期检索集合获得，可能延迟一块看到正确历史；整段 3000 块测试只覆盖写路径。系统时序主要来自一台机器、一个起始场景及一个种子；并未达到实时 16 fps，长期生成有与量化无关的纹理漂移。RoPE 重映射质量依赖场景。

## Future Work
作者提示可与更高效的 KV 压缩和几何路由结合；需在不同硬件、真正实时和更多具检索收益的模型上验证，并解决长时纹理漂移与过期集合的语义代价。

## Rating
创新度评分：3/5 - 利用位姿可预知访问这一特性完成 NVMe 分层零等待推理，量化和位置重映射本身已有先例。
相关度评分：3/3 (Core) - 直接解决交互式视频世界模型的长程记忆与推理容量问题。

## TL;DR
将历史KV分层存到NVMe并按位姿预取，使单卡视频世界模型连续生成37.5分钟，系统方向值得精读。

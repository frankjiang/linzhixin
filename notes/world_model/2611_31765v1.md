# Dreamcatcher: Remembering What Surprises a World Model in Video Streams

## Insight
观察：视频中“变化大”可能只是可预测的重复动作，细微但违背预期的事件反而更值得记住；检索相关的旧片段也可能不给当前问题增加证据。推论：冻结视频世界模型的潜在预测误差可指导无查询时的记忆形成，而读历史前要判断其相对当前画面的增量证据。等保留预算下，V-JEPA 2 惊奇度在 OVO-Bench 上比帧差高 3.9–4.5 个百分点（Qwen3-VL-8B）；证据门相较直接读 Top-4 再增 1.9 点，支持两阶段设计。

## Motivation
直播视频问答必须在未来问题未知时，单次流式编码并压缩长历史。冗余/帧差保留策略难区别预期动作与真正异常，单纯相似度检索又会读入无用历史；这会浪费内存和回答 token。论文虽以视频问答为终端任务，但其世界模型预测误差驱动的在线记忆选择，对长时视频世界模型有直接方法借鉴。

## Method
冻结 V-JEPA 2 用先前 14 秒、4 fps 画面预测到来的 2 秒潜在 patch 特征，按通道历史误差尺度归一化并截断预测残差；平均成时间惊奇度以切分视频，空间误差映射到冻结 Video-LLM 的原生视觉 token 网格。每段预算随年龄按 `ρ+(1−ρ)e^(−a/T)` 衰减，默认下限 ρ=0.3、T=20 秒；一半预算用最远点采样保覆盖，一半给高惊奇度 token，保留最近 4–7 帧的完整锚点。问题到来时用 PE-Core 相似度列出最多 12 段，逐段让 Video-LLM 判断其相对当前锚点是否有新增证据，按 Yes/No logit 差选最多 4 段回答。V-JEPA、检索编码器和阅读器均不训练。

## Experiment
在 OVO-Bench、StreamingBench、StreamBench 和三项离线长视频基准上，用四种冻结 Video-LLM 比较同阅读器的训练免调方法。Qwen3.8-27B 在 OVO-Bench 达 78.9%，基座 73.2%、FluxMem 75.5%；StreamingBench 为 79.7%，StreamBench 为 75.1%。OVO 中三种 Qwen 阅读器的最终回答输入 token 比 1 fps 基座少逾 80%；但 Qwen3.8 的问答总延迟从只读当前锚点的 0.49 秒、直接 Top-4 的 1.02 秒升至证据门的 3.20 秒。预算消融显示默认 45% 历史 token 的 78.9% 准确率，接近固定 50% 保留的 78.8%；补充实验报告 V-JEPA 惊奇度、检索门和时间预算各自收益。

## Value
**值得精读**。可直接借鉴“预测误差决定写入、当前视图的增量证据决定读出”的记忆分工，以及覆盖采样防止只保留异常片段。适合研究长时视频/隐式世界模型的记忆压缩与检索；若只做动作条件生成，论文的问答门控须重新设计。

## Strengths
使用独立预训练、冻结 JEPA 预测器，能隔离惊奇度信号而非靠联合训练获益；多阅读器、多基准与等预算信号消融较完整；同时报告保留量、最终输入 token、额外问答延迟及内存。

## Weaknesses
这是基于世界模型的流式问答记忆系统，未验证生成式世界模型中的状态持久性、三维一致性或控制收益。记忆下限使总存储随视频长度线性增长，读出虽有上限但不能无限时长固定内存。V-JEPA 只看中心裁剪的低分辨率画面，侧边细节可能没有惊奇分数；证据门增加约十次阅读器打分，延迟明显。论文的“超过 80% token 节省”仅计最终回答输入，未包含门控额外预填充；部分外部基线使用论文复现与调参版本。

## Future Work
作者未给出具体模型升级路线；局限中指出部署需额外约 3.7 GiB 辅助模型权重、主机内存存储，以及阅读器暴露原生视觉 token 和首 token logits 的接口。延伸方向是降低门控打分成本、处理图像边缘事件和控制长期记忆增长；这些属于据局限提出的建议。

## Rating
创新度评分：3/5 - 将独立 JEPA 潜在预测误差用于在线 token 记忆，并配合增量证据门，具有清楚的机制消融；核心组件仍为现成模型与启发式预算。
相关度评分：2/3 (Related) - 不训练视频世界模型，但直接把 V-JEPA 的预测信号用于长视频记忆管理，可迁移到相关系统。

## TL;DR
用 V-JEPA 潜在预测误差保留惊奇片段，再以增量证据门检索视频历史，显著省回答 token；长时记忆设计值得精读。

# Governed Persistent Memory: Source-Bound State Semantics and Fail-Closed Release for Long-Horizon Agents

## Insight

论文的关键观察是：“能检索到”与“当前有权公开断言”是两个不同问题。一个高相关记录可能已被新事实取代、处于冲突、被撤回/删除，或仅是未经验证的原始 testimony；若仍按相似度直接注入生成，持久化会让一次错误不断被召回和再写入。作者由此推论，长时记忆的公共输出必须建立在显式状态语义上：来源绑定、双时态、冲突隔离和当前删除屏障先决定 eligibility，检索只负责排序；最终结构化 claim 还须在同一个稳定 ledger head 上重新闭包检查并 fail closed。论文通过五项可执行义务、移除保护项的反例、有限状态穷举和多实现 differential test 支持该系统性质，但证明的是合成契约一致性，不是事实真实性或开放语言正确性。

## Motivation

现有 agent memory 多按 select–store–retrieve 优化召回，却没有统一回答来源是否可信、晚到事件属于哪个时间、相互矛盾记录能否发布、删除后历史快照是否会“复活”等治理问题。这对长期个人记忆、隐私和审计是重要系统问题。相关工作分别处理 CRDT 冲突、双时态操作、证据角色或派生物修复；GPM 希望覆盖从来源登记到结构化输出的一条端到端公共状态契约。该问题属于 LLM agent memory/database governance，与视频、3D 或隐式世界模型没有实质技术重合。

## Method

GPM 把记忆实现为 hash-chain append-only event ledger。事件带连续序号、transaction time、可选 valid time、payload、前驱和规范哈希；另有受保护的 head/索引 commitment。状态由 ledger、claims、provenance、barrier 和可重建索引组成，生命周期从事件推导而非由调用方任意写标签。主要事件包括 episode.add、fact.assert/quarantine/retract 与 user.delete。

五项义务为：

- I1 ledger integrity：序号、前驱、哈希、segment/index commitment 一致，否则公共读取停止。
- I2 syntactic source binding：公共 fact 必须直接绑定同用户 source bytes、quote 和位置；仅验证字符串来源，不验证语义蕴含。
- I3 conflict isolation：同实体、单值属性、重叠有效时间且值不同的未解决 claims 不能同时可断言。
- I4 public non-revival：即使查询过去 transaction prefix，也应用当前 head 的撤回/删除 barrier，阻止旧 fact、episode 或索引复活。
- I5 structured release closure：外部生成器提出结构化 claim 及 source fact ID；本地 gate 在读取 head、重建新鲜 public view、逐 claim 精确匹配后重读 head。集合非空且全闭包且 head 未变才 release，不闭包则 abstain，head race 则报错且不生成记录。

系统提供 strict 单文件、incremental 与 segmented 三种 engine；公共视图与授权 audit/as-of 视图分 API。记录绑定 claim multiset digest、query、用户、时间、policy/normalizer 版本和 head，但未签名，不能作为跨进程凭证。整体更多是数据库、provenance 和安全契约的组合，而非学习算法。

## Experiment

主评测 GPM-ReleaseBench 是项目内部生成、冻结并隐藏 evaluator 的 3,600 个 case，含 12 类来源错绑、跨用户混合、冲突、晚到双时态、撤回/删除复活、索引完整性、head race 和闭包等场景，组成 1,800 对最小反事实。对照 raw append、latest-first、flat conflict-preserving 和 GPM，指标为完整输出匹配、answer bundle accuracy、违规 case 的 unsafe release 和 safe coverage。

GPM 达 3,600/3,600、100% answer accuracy、0% unsafe、84.62% coverage；最强简单完整策略为 1,800/3,600、52.17%、50%、61.54%。StateFuse 只在共同支持的 2,100 case 上测得 1,200 匹配和 62.5% coverage，不能据此作全局排名。后验移除 I1–I5 各自造成 150、150、150、600、750 个完整输出错误，其中 I2/I3/I4/I5 分别暴露 150/150/450/750 次 unsafe release。

Governed-QA Sealed 经真实 ingestion/release service 测八类、每类 300 个合成 cluster；确定性 governed lane 在 V3 为 2,400/2,400，而无治理的本地 Qwen2.5-7B 为 600/2,400。V5 固定生成日期后，中英文两臂也各 2,400/2,400；这些 100% 是显式语法/契约 oracle，不是语言模型正确率。独立有限模型遍历 331,776 个语义状态和 1,990,656 个查询状态，完整契约无反例且六个 guard mutant 均有反例；100K 随机 trace 的三 engine 无差异。incremental 中位吞吐约 44,156 events/s，较 strict 的 12,295 提升 3.565×。

公开 clean-task 中 flat 与 GPM 获得字节相同候选，结构性答案差为零，只能说明没有额外退化；LongMemEval 的两版 AI judge 均未通过预设一致性 gate，作者正确地不把其答案率作为主证据。

## Value

GPM 对长时智能体系统的价值在于把“删除、冲突、来源和输出授权”变成局部可执行契约，并对 claim-set 完整性与读写 race 给出清晰边界。其审慎的 evidence hierarchy 和负结果披露也值得参考。但它没有 learned latent、环境动力学、预测、规划或 imagination；把 persistent memory 称为 agent state 并不使其成为用户关注的 world model，故在本综述中只应记录为噪声项而非主线文献。

## Strengths

- 对“相关性不等于可发布性”的系统边界定义准确，明确区分 storage/state/retrieval/language 四层失败。
- 形式语义、三种实现、隐藏合成测试、bounded exhaustive check 与 differential trace 构成多层验证。
- 作者反复限定 100% 结果只属于内部契约，并如实披露日期 reducer 修订和 language judge gate 失败。
- fail-closed head reread、完整 claim multiset digest 与当前删除屏障针对真实工程 race 和非复活问题。

## Weaknesses

- 两个主 benchmark 均由同一项目内部合成，ontology、实现和 gold 非独立；简单 baseline 也远弱于完整现有 memory systems。
- I2 只检查 quote 字节存在，不验证 claim 是否由文本语义蕴含；I5 也不验证回答 query 的相关性，更无法约束最终自由文本中的隐式断言。
- 删除仅是公共视图 barrier，不是物理擦除、备份删除、密钥销毁或 machine unlearning；任意下游 summary/cache/embedding 也不会级联撤回。
- threat model 信任 engine、时钟、协调和独立 commitment，无法防恶意授权 writer 或同时改写数据与 commitment 的主机攻击者。
- 多值 schema、实体共指、模糊时间、单位转换和开放文本冲突均未处理；有限状态遍历也不是无界形式证明。
- artifact 尚未公开，隐藏 gold、receipt、模型 prompt 和授权数据不提供，当前不能由外部团队完整复现。

## Future Work

作者提出外部编写的挑战集、公开 artifact/密封 receipts、独立复现、任意派生物级联修复、更丰富的 typed conflict、自由文本 evidence closure 和长期用户研究。工程上还需加入可认证跨进程凭证、真正访问控制与密钥管理、物理删除策略及分布式一致性；若要服务生成式 agent，还必须建立语义蕴含、query relevance 和自由文本输出检查层。

## Rating

创新度评分：2/5 - 将成熟的双时态、provenance、hash ledger 和 fail-closed 检查组合为完整记忆发布契约，验证认真但主要是系统整合，且核心 benchmark 内生。

相关度评分：0/3 (Noise) - 研究 LLM 长期记忆治理与数据库状态语义，不包含视频/3D 预测、JEPA/Dreamer latent 动力学或模型式控制。

## TL;DR

以双时态来源账本约束长期记忆发布，契约验证严谨但与目标世界模型无关，可跳过。

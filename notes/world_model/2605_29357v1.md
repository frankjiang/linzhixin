# PassNet: Scaling Large Language Models for Graph Compiler Pass Generation

## Insight
无与世界模型相关的insight。本文研究LLM生成编译器图变换pass（pattern matcher + rewriter），发现long-tail子图占43%实际workload且TorchInductor处理不好，而LLM在个别子图上可达3×加速但一致性差。

## Motivation
- 问题：TorchInductor等张量编译器对long-tail算子组合处理不佳（43%子图有端到端减速）
- 同行：现有LLM for compilers工作聚焦kernel generation（生成独立GPU kernel），而非pass generation（结构化图变换）
- 关键性：pass generation保持与编译器pipeline的可组合性和可验证性

## Method
- PassNet-Dataset：从100K模型提取18K unique计算图，通过Recursive Folding和Prefix Analysis生成279K子图
- PassBench：200个long-tail fusible任务，Error-aware Speedup Score (ES_t)联合评估正确性+性能
- 评估完整性防御：AST inspection防计算委托、Dispatch Interception防动态逃逸、Reverse Evaluation防cache pollution
- PassAgent：迭代式agent框架（file_editor + pass_evaluator）

## Experiment
- 评估6个前沿+开源模型，Claude-Sonnet-4.6最强(AS=0.448)但仍落后TorchInductor 37%
- 个别子图LLM达3.02×加速（识别composite intent能力）
- Fine-tuning 4K trajectories: Qwen3-30B-A3B获得2.67×提升
- 瓶颈：一致性而非能力——模型难以跨diverse patterns可靠泛化

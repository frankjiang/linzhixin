# Code to Control: Synthesizing Parameterized Reactive Controllers

## Insight
对当前结构化状态已足够决定动作的任务，可把计算前移到控制器合成阶段，推理时直接执行程序。作者以 Atari/Flappy Bird/MuJoCo 的回报与延迟验证：Pong 决策约 11.4 微秒，对比 WorldCoder 规划摊销约 46 毫秒。该结论的适用边界是短期反应式控制，不能推断世界模型在需长远预测时无用。

## Motivation
LLM 逐步出动作慢；用 LLM 写转移模型再每步规划，亦有延迟和多步误差。作者针对结构化观测且反应式规则容易表达的环境，直接合成策略程序并用环境奖励优化其参数。

## Method
离散任务输入 OCAtari 提供的对象类别、框、速度，由 LLM 编写 Python `policy(state)`；每回合把轨迹和回报反馈给 LLM 修订，保留历来最好版本。连续 MuJoCo 中 LLM 从随机交互转移写 14 维特征函数，标准化特征后由增广随机搜索 ARS 拟合特征到各执行器的线性矩阵 W；各特征库独立生成，不随拟合回报修订。推理阶段只有程序/矩阵运算，不生成或滚动世界状态。创新主要是 LLM 程序结构和无梯度参数拟合的分工。

## Experiment
6 个 Atari 游戏以三随机种子的“单次运行最好回合分数”中位数评价，并统计环境步数、token 和决策延迟。Pong 为 +18，WorldCoder -19、ReAct -17、PPO 20M 步 +21；Space Invaders 为 490，对比 PPO 20M 步 115。Flappy Bird 在基础环境存活至 20,000 步上限，对 8 种物理变化，部分零样本适应，参数重拟合后 5 个失败变化中的 3 个恢复全程存活，重力反向仍失败。10 个 MuJoCo 任务中 9 个超过 WorldCoder/GIF-MCTS；HalfCheetah 回报 3958.95，Reacher 不如规划基线。注意 MuJoCo 并未做匹配交互预算，PPO 对比主要在 Atari；Hopper/Walker2d 的回报含生存奖而位移很小。

## Value
对世界模型团队的启发是设置简单、低延迟的反应式策略作为比较基线，并明确哪些任务需要反事实预测/长时规划。本文不提供视频、3D 或隐式世界模型方法。

## Strengths
真实报告程序执行延迟、LLM 调用和交互成本；用物理扰动测试程序结构与常数参数的适应边界；承认奖励与实际运动目标可能不一致。

## Weaknesses
依赖预处理的对象级状态和关节状态，未直接处理像素；Atari 主指标是“最好一回合”而非稳定策略平均表现，易高估可靠性。连续实验不匹配样本量；从一篇已发表工作引用 CQL/Oracle 数字，不完全同条件。离散程序修订 72% 回合不及运行最佳版本，结构变化会毁掉有效规则；复杂部分可观察任务不适用。

## Future Work
作者明确提出寻找程序结构修订与固定结构参数适应的平衡；像素输入、长时规划任务也仍在当前方法覆盖范围之外。

## Rating
创新度评分：2/5 - LLM 写程序加 ARS 调参属已知模块的实用组合，对世界模型本身没有新机制。
相关度评分：1/3 (Tangential) - 仅作为无需世界模型的控制基线和适用边界参考。

## TL;DR
合成可直接执行的反应式控制器，显著降低决策延迟，但未建世界模型；比较基线可选读。

# Planning with Transformers: Chain of Computation and Structured Context Windows

## Insight
有。Observation 是 Transformer 理论上图灵完备，但一次性从 prompt 生成完整计划时泛化很差；真正难点是让模型学可复用的局部算法步骤和外部工作记忆。推论是把 Transformer 放进循环中，用结构化上下文窗口充当可写 tape/stack，可以把规划泛化从“长输出生成”转成“局部转移执行”。

## Motivation
解决 LLM/Transformer 在符号规划上难以外推的问题。同行多靠 CoT、搜索或更长上下文，但容易随问题规模爆炸。这个问题对 planning 有理论价值，但不是用户关注的视频/3D/隐式 world model。

## Method
提出 Chain of Computation (COC)：Transformer LM 每步读取当前 instruction/pointer，在 Structured Context Window 中写入新 instruction、action 和 pointer。模型同时学习 planning policy、state transition 和指针/栈操作。Tower of Hanoi 还测试 PDA stack variant，避免显式 pointer arithmetic。训练用从 scratch decoder-only Transformer，监督每条局部 instruction 的 prompt-target。

## Experiment
在 Tower of Hanoi、BlocksWorld、Extended BlocksWorld、Pancake 上评测。BlocksWorld/Pancake 对 n=5..40 训练、未见配置测试几乎 100% 成功；Extended BlocksWorld 99.89%。TOH 在 holdout 较大时失败更多，错误主要来自未见 disk id/instruction number 与 pointer arithmetic；PDA stack 版本在 n=1..20 达 100%。数据缩放显示 100 个训练实例已接近完美，5 个不够。

## Value
对世界模型研究的启发是：规划能力可能需要显式外部状态和过程化执行，而不只是更大上下文。对视频/3D WM 不是直接参考，更适合做 planning abstraction 的旁读。

## Strengths
把 Transformer planning 的泛化问题拆得清楚；COC/SCW 给出可运行机制；多符号域和数据量消融支持论点。

## Weaknesses
任务是干净符号规划，远离感知、连续控制和真实 world model；训练数据由算法轨迹生成，泛化范围仍依赖任务结构；不解决学习环境 dynamics 的问题。

## Future Work
作者提出研究 pointer vs full context 的理论影响、更多规划算法，以及 SCW 对学习和泛化的作用。

## Rating
创新度评分：3/5 - 对 Transformer 规划接口有清晰机制创新，但应用域窄。
相关度评分：1/3 (Tangential) - 与世界模型规划有抽象联系，但不是视频/3D/JEPA/Dreamer。

## TL;DR
COC把Transformer放入带结构化上下文的循环来学符号规划，规划理论可选读，世界模型主线可跳过。

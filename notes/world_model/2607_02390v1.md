# DecompRL: Solving Harder Problems by Learning Modular Code Generation

## Insight
主要 insight 是把代码生成从“一次生成完整程序”改为“先分解模块，再组合多个模块实现”，可把候选程序数量从线性采样放大为组合式搜索。Observation 是复杂编程题往往可分解成函数，若每个函数有多个候选实现，最终程序可通过笛卡尔积组合并由 CPU 测试筛选。论文据此把扩展瓶颈从 GPU 生成转移到便宜的 CPU evaluation。

## Motivation
论文解决 LLM 代码生成在 hard programming problems 上的搜索效率。同行使用 pass@k、GRPO、logmeanexp 等整程序采样和 RL；这些方法需要大量生成 token，且难利用模块结构。该问题属于代码生成，不是视频/3D/隐式世界模型的关键问题。

## Method
DecompRL 学习 decomposition policy 和 implementation policy。模型先把问题拆成多个函数，再为每个函数生成多个实现，并组合成 K^N 个完整候选。训练目标用 logmeanexp 近似 pass@k 的可微优化，使模型偏向产生可组合、可测试的模块。论文中出现的 “Code World Model” 是代码模型名，不是本任务关注的 world model。

## Experiment
使用 Qwen2.5-7B、Llama3.1-8B、Code World Model-32B，在 CodeContest/TACO 训练，评估 CodeContest valid 和 LiveCodeBench。LiveCodeBench 上 Qwen 在 100K token budget 下 DecompRL 得分 0.44，高于 pass@8 的 0.41 和 lme16 的 0.40；500K 时 0.48，对比基线约 0.46。低预算下 DecompRL 不占优。消融显示无 RL 的层级生成表现差，模块 RL 是关键。

## Value
对目标方向参考价值有限。可借鉴的是“结构化生成 + 外部验证 + 组合搜索”的思想，可能类比到程序化 world model 或符号模型修复，但与视频/3D/latent world model 没有直接技术交集。

## Strengths
把模块化结构和可执行测试结合，搜索扩展思路清楚；在高 token budget 和 hard subset 上有效；训练/评估规模较大。

## Weaknesses
与 world model 研究方向基本无关；方法依赖测试用例和可组合函数边界；低预算不如常规 RL；存在分解退化、reward hacking 和 off-policy 训练成本问题。

## Future Work
作者提到未来可做 explorer/distiller pipeline，缓解离策略训练、分解质量和效率问题。

## Rating

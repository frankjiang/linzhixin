# The Robot Data Factory

## Insight
观察：动作、视频或成功率单独记录，都不能还原机器人与环境的物理交互；任务失败也可能产生有价值的数据。推论：应把具身经验组织为带有任务、机体、同步传感器、动作及结果的可追溯记录，并分开评价观测质量与物理能力。这是基础设施设计原则；现有部署展示了可实现性，尚未证明它能提高世界模型学习效率或跨机体泛化。

## Motivation
现有数据集、遥操作系统、仿真器和基准通常彼此割裂，缺少统一的任务协议、时间同步、失败标签及机体能力描述。论文希望将一次性收集升级为持续的“部署—测量—学习—再部署”。对动作条件世界模型而言，动作与物理结果的对应、失败数据完整性、训练评测可复现性确实关键。

## Method
- 用 Mission→Task→Skill 组织任务，Episode 保存一次执行；Chamber 提供可重复的物理场景。已建设家庭、海洋环境、能源巡检三个场景，连接不同机器人、外部追踪及遥操作设备。
- 记录指令、场景配置、机体状态、多模态观测、动作、外部真值、元数据和评分；由同一记录构造策略训练样本或多步动作条件未来预测样本。保留有效记录中的任务失败，另行处理损坏数据。
- Mission-Control 检查设备与记录就绪状态；管线依次采集、打包、验证、整理、版本化发布。实时控制与大文件传输分流，统一时间基准，使用对象存储和分层保留策略。
- Pitstop 将人类参考、遥操作、共享控制、自主策略、世界模型预测与数据质量分轨。任务得分采用安全/数据门控、任务内加权指标和难度系数，避免成功率掩盖无效数据或危险行为。
- 附录 B 分离采集字节、保留字节、模型 token 和算力成本；依据传感器速率、表示、数据选择、训练周期及实测利用率估算基础设施。主要是系统集成与规划模型，未提出新的世界模型算法。

## Experiment
没有世界模型训练对比、学习收益消融或跨场景泛化实验。

- **部署证据**：附录 C 的界面快照报告 82 个 sessions、71 个通过验证的 packages、5 个整理数据集/内部 releases、0 个 published entries；约 385 GB、160 条流。这是部署快照，不能视为公开数据集规模或长期稳定性测试。
- **规划计算**：假设 120 台标准配置机器人全天运行，保留速率约 4.61 GB/s、每月 11.95 PB；采集写入约 6.50 GB/s。全流训练假设下，7B 模型每月一遍对应约 2,566 个参考加速器，选择/复用场景可降到约 650 或 170。均为假设驱动的容量推算，非实际集群测量。
- **评测设计**：任务成功、安全、耗时、位姿/放置误差、最终状态质量，以及流完整性、时间偏移和丢包。任务故事板中的阈值是拟议协议目标；能力增长示意图不代表实验曲线。
- 推理分析引用 GR00T-N1.7 的 H100 27.9 ms 外部结果；其他 GPU 延迟按带宽外推，并非本文硬件实测。

## Value
适合建设具身数据平台时参考，尤其是失败数据保留、动作/观测同步、外部物理真值和按自主程度分轨评测。对世界模型研究的启发是：数据质量应由能否支持可靠的干预预测来衡量，而不是仅统计视频时长。其基础设施规模并不直接等于模型能力。

## Strengths
- 把数据有效性与任务成功分开，明确保留可解释的失败轨迹。
- 跨机体、跨场景保留物理上下文与数据血缘，具有直接工程价值。
- 附录明确区分存储压缩与学习表示，并披露容量估算的假设和敏感性。

## Weaknesses
- 核心学习闭环、联邦协作及公开发布仍是后续计划，缺少模型收益和长期运行证据。
- 难度系数、评分权重和跨机体可比性尚待经验校准；统一 schema 本身不能解决动作语义和动力学差异。
- 算力结果高度依赖全天工作率、标量 token 化、复用系数等设定；借用语言模型的计算最优比例不能证明机器人模型的收敛需求。
- 篇幅较长，概念与工程框架重复较多，直接服务视频/3D/隐式世界模型的技术创新有限。

## Future Work
作者计划运行标准任务、验证协议、发布首批带评分脚本的数据与基准，扩展数字孪生、场景和机体，逐步建立跨实验室共享的接口与治理机制。数据对学习和跨机体能力的实际贡献仍需下一阶段实证。

## Rating
创新度评分：2/5 - 统一具身经验生产与评测流程有工程价值，但缺少新的世界模型技术及学习效果验证。
相关度评分：2/3 (Related) - 可直接借鉴世界模型的数据采集与评测设计，主体是机器人基础设施。

## TL;DR
以任务、同步多模态记录和分轨评测构建机器人数据工厂，模型收益尚未验证，数据工程部分可选读。

# Programmable World Model

## Insight
观察：视频看起来连续，并不意味着离屏实体、血量和交互规则持续正确；完整几何又要求推理时生成复杂动画。推论：用粗粒度、可执行的世界状态规定事实，让视频模型补全外观与细节。3D OBB 是两者之间的接口。证据是状态一致性对比实验，尚无表示粒度消融来证明 OBB 最优（§2、§5）。

## Motivation
交互世界需要实体寻址、离屏记忆和可编程规则。现有视频记忆主要维持画面；StatePlay、MASS 等仍依赖学习的状态转移。本文把规则执行交给引擎，解决游戏生成中的关键可控性问题，但不以学习未知物理规律为目标。

## Method
1. 单张图像经 3D 检测初始化实体；编码智能体结合自然语言生成属性、关系、事件和规则程序。
2. 引擎执行动作，更新世界坐标中的 OBB、身份、血量等状态；确定性编译器投影出身份、语义、运动方向三类像素对齐条件。方向由世界速度变换到相机坐标后量化为七类，区分物体运动与相机运动。
3. 冻结 LingBot-World-v1 主干和相机模块，训练空间 ControlNet。分块生成结合多尺度时间历史、首帧锚点及继承自 AlayaWorld 的几何重投影记忆。
4. 训练标注来自游戏录像，经 ViPE、Qwen3-VL、SAM3、WildDet3D 提取相机、深度、轨迹与语义（§4）。创新主要是可执行状态与生成渲染的系统接口。

## Experiment
- CombatStateBench：50 段战斗序列，400 个采样帧、50 次死亡事件。Qwen3.6-27B 仅看生成 RGB 评判；对手通过提示切换接收事件。
- 表1：Count Accuracy 为 **94.00%**，LingBot-World-V2 / YUME 为 40.75% / 32.00%；State Accuracy 为 **98.00%**，对手为 8.00% / 58.00%。后者只要求事件后三帧中至少一帧出现死亡角色，**不核验是否死对了实体**。
- VBench 成像/主体/背景/时序稳定性为 67.62/94.74/96.98/99.00；成像质量相对 LingBot 的 67.46 仅小幅提高。图4–5展示转身发现离屏角色、异类实体和 897 帧长序列，属于定性证据。
- 未报告模块消融、运行帧率、训练数据规模或统计误差。

## Value
值得借鉴的是“哪些事实必须显式保存、哪些细节可以生成”的设计边界。适合可编程视频/3D世界；对隐式动力学学习的帮助有限。下一步应验证渲染结果是否持续忠实执行复杂状态，而不只验证引擎自身正确。

## Strengths
- 状态可编辑、可验证，离屏实体和非视觉变量都有明确归属。
- OBB 控制不要求完整网格或骨骼；自动标注管线便于扩展。
- 把状态一致性纳入评估，比单纯视频观感更贴近交互需求。

## Weaknesses
- 基准小且围绕自有状态接口构造；结构条件与仅文本提示的信息量不对等，无法归因到单一技术。
- 粗粒度 VLM 判分不证明身份级一致性；未见人工校准及复杂规则、碰撞、多人交互的系统验证。
- 动力学正确性依赖程序与初始化，细粒度接触仍由生成先验补全；实时可玩性缺少速度证据。

## Future Work
结论提出“可执行、可验证状态 + 生成外观”的发展方向；未给出具体未来实验或优化路线。

## Rating
创新度评分：3/5 - 系统组合与状态接口有价值，但沿用生成渲染和记忆模块，消融与规模证据不足。
相关度评分：3/3 (Core) - 直接研究可编程视频世界及显式3D状态控制。

## TL;DR
用可执行三维盒状态驱动视频渲染，显著改善实体与事件一致性；值得精读接口设计，但须警惕粗粒度评估。

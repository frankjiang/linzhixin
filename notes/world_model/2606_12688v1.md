# M*: A Modular, Extensible, Serving System for Multimodal Models

## Insight
核心 insight 是现代多模态/世界模型推理不再是单一 autoregressive loop，而是异构组件图上的不同 walk；serving 系统应抽象为 Walk Graph，以表达 sequence/parallel/loop/stream/dynamic-loop 和细粒度 placement。

## Motivation
解决 vLLM-Omni/SGLang-Omni 等 stage-DAG 对 composite multimodal model 支持不足的问题：图像生成有 diffusion/flow loop，world model 有 variable-horizon rollout，TTS 有 streaming，VLA 有动作生成。与世界模型相关的是 serving/runtime，不是模型方法本身。

## Method
M* 中模型声明为 (G,W)：G 是组件 dataflow graph，W 是命名 Walk 集合，每个 request 根据 state machine 执行一串 walk。提供 GraphNode/GraphEdge、Sequential、Parallel、Loop、DynamicLoop、StreamingGraphEdge 和 chunk policy。Runtime 负责 scheduling、batching、tensor transport、KV cache、CUDA graph、paged attention、placement。组件可按 node 级 tensor parallel/placement，支持同一逻辑节点在不同 Walk 上不同部署。

## Experiment
评估 BAGEL、Qwen3-Omni、Orpheus、V-JEPA2-AC。BAGEL T2I/I2I 上 M* 对 single-stage vLLM-Omni p50 latency 提升 1.25x/1.22x，对 default I2I 提升 2.64x；I2T batch 16 throughput 提升 32.7%。V-JEPA2-AC rollout 在单 H100、B=1、DROID 前 50 episodes，DynamicLoop + KV cache 相比 Meta 原生 Python autoregressive loop：H=4/15/30 p50 speedup 2.08x/3.76x/12.5x。

## Value
对部署长 horizon world model 很有实际价值，尤其是把 rollout horizon 当 DynamicLoop 并复用 KV cache。但它不是世界模型算法论文；若关注系统服务化、推理延迟、在线规划吞吐可读，否则可略读。

## Strengths
亮点是对部署长 horizon world model 很有实际价值，尤其是把 rollout horizon 当 DynamicLoop 并复用 KV cache。

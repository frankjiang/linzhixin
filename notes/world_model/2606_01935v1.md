# Unified Driving Tokens: Representation- and Geometry-Guided Discrete Tokenizer for Driving World Models and Planning

创新度：3/5 | 相关度：2/3

## Insight
核心insight：自动驾驶中的discrete visual tokenizer需要同时服务两个下游任务（世界模型生成 + 规划），但现有tokenizer继承自图像生成领域，仅针对像素重建优化。论文发现一个关键矛盾：当离散token需要同时编码appearance（用于生成）、semantics（用于规划）和geometry（用于状态估计）时，单codebook容量不足会导致各目标互相竞争——特别是加入几何监督后PSNR下降。通过multi-codebook quantization可以缓解这一capacity bottleneck，在不增加token分辨率的前提下扩大表征容量。

## Motivation
- **问题**：自动驾驶的离散视觉token应同时作为world model的预测目标和planner的输入表示，但现有方案（如DrivingGPT的LlamaGen tokenizer）仅优化像素重建，token语义与驾驶决策需求之间存在gap。
- **同行做法**：DrivingGPT、Orbis等使用标准VQ-VAE/VQGAN tokenizer，优化重建后才评估规划性能，未将planning consumability作为tokenizer学习的first-class目标。
- **是否关键**：tokenizer是token-based world model的基础组件，其设计直接影响生成质量和规划性能，问题定义准确。

## Method
**Tokenizer Encoder：**
- 双分支输入：frozen DINOv3-B提取语义特征 + 轻量RGB detail encoder提取纹理/边界细节
- 融合后通过pre-norm Transformer（RoPE）编码，经VQ量化产生离散token

**训练目标（联合多目标）：**
- 外观：pixel-wise L2 + LPIPS感知损失 + GAN对抗损失 → 重建RGB
- 语义：cosine similarity + MSE → 重建frozen DINO特征
- 几何（cross-frame）：相邻帧token经temporal aggregator（VGGT-style spatiotemporal attention）解码depth和relative pose
- VQ：EMA更新codebook + commitment loss + dead-code reinitialization + orthogonality regularizer

**Multi-Codebook Quantization：**
- Attention-based splitter将pre-quantization feature拆分为M个head，每个head独立量化到各自codebook
- Split-and-merge：M个codeword通过线性映射融合回单一embedding
- 有效增加表征容量（M个indices per patch）而不改变token分辨率

**下游评估（frozen tokenizer）：**
- Planning：轻量trajectory decoder（20M参数），从frozen token features预测多条轨迹 + scoring head
- World Model：GPT-style autoregressive Transformer（1B参数），AdaLN conditioning，next-token prediction

**创新程度**：将representation alignment、geometry supervision、multi-codebook VQ统一到一个driving tokenizer框架中，各组件虽非全新但组合有一定新意。

## Experiment
**数据集/基准：** NAVSIM（基于OpenScene/nuPlan，~120h驾驶数据），单前视camera。

**Tokenizer质量：**
- vs LlamaGen：rFID 4.15 vs 5.67, PSNR 26.51 vs 23.09, SSIM 0.774 vs 0.652
- vs Orbis：rFID 4.15 vs 5.53, DINO feature距离显著更低（cos 0.0453 vs 0.0595）

**规划性能（NAVSIM PDMS）：**
- 单视角token-based方法最佳：PDMS 91.8（超过DriveLaW 89.1, PWM 88.1, Epona 86.2）
- 也优于多数端到端多传感器方法（vs DriveSuprim 93.5使用camera-only，但DriveSuprim是end-to-end非token-based）

**Tokenizer消融（Planning PDMS）：**
- Naive reconstruction → 85.5; +Rep → 89.4; +Geo → 90.9; +MCB → 91.8
- 每个组件都有正向贡献，验证了设计的必要性

**世界模型生成：** 在matched setting下FID和FVD均优于DrivingGPT baseline

## Value
这是一篇质量不错的driving world model tokenizer工作，核心贡献在于明确提出tokenizer应jointly optimize for generation + planning，并给出了representation-guided + geometry-enhanced + multi-codebook的具体方案。对视频世界模型方向密切相关：(1) 展示了将foundation model特征（DINO）注入离散tokenizer的有效路径；(2) multi-codebook VQ缓解capacity bottleneck的技巧可借鉴；(3) 几何监督使token具备3D awareness的思路值得参考。

来自北大+小米EV的合作，工程完成度高。待解决：(1) 仅单前视camera；(2) tokenizer和world model/planner仍分阶段训练，未实现真正联合优化；(3) 几何监督仅用于训练时，推理时是否真正编码了几何信息需进一步验证。

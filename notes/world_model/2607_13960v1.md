# GigaWorld-Policy-0.5: A Faster and Stronger WAM Empowered by AutoResearch

## Insight
核心 insight 是：World Action Model 的未来视频预测可以主要作为训练期监督，而不是部署期负担。Observation 是 WAM 推理时生成未来视觉会显著拖慢控制频率；推论是让 action token 在训练时受未来视觉动力学约束，但部署时只解码动作，可以保留世界模型监督收益同时降低延迟。

## Motivation
论文解决机器人 WAM 在真实控制中慢的问题。同行包括 pi0.5、FastWAM、GigaWorld-Policy 等 VLA/WAM，或直接预测动作，或在推理时显式生成视觉未来。关键问题是机器人闭环控制需要低延迟，世界模型若每步都生成视频，难以部署。

## Method
方法是 action-centered WAM。输入多视角观测拼接图、机器人 proprio state 和语言指令，训练时联合预测动作 chunk 与未来视觉；因果 mask 让未来视觉 token 可以看动作 token，但动作 token 不能看未来视觉，保证部署时可移除未来视觉分支。架构上使用 Mixture-of-Transformers，视觉专家继承 GigaWorld-1，动作专家由视觉权重初始化并缩小，二者通过多模态 self-attention 交互。目标是 action flow matching 加 future visual flow matching。训练包括 2K 小时机器人数据预训练、AC-WM 监督、目标机器人后训练，以及 AutoResearch 搜索学习率和 batch size；部署侧用 KV cache、torch.compile 和 C++ runtime 加速。

## Experiment
真实机器人为 AgileX PiPER 6-DoF。评估 fruit picking、object placement 和长程任务，指标为成功率和延迟。Fruit picking 平均成功率 0.85，高于 pi0.5 0.76、Motus 0.80、FastWAM 0.78、GigaWorld-Policy 0.80；placement 平均 0.89，高于 0.76/0.83/0.77/0.81；长程任务平均 0.77，高于 0.50/0.57/0.47/0.53。延迟上 A100 约 189 ms，RTX 4090 Python 约 110 ms，C++ runtime 约 85 ms。AC-WM 消融显示未来视觉训练监督加快收敛并提升最终成功率。

## Value
对我们有直接启发：视频世界模型监督未必必须在推理时显式生成视频，可以作为 representation/action learning 的训练约束。这个思路适合高频机器人控制，也提示“训练期世界模型、部署期策略”的折中路线。

## Strengths
切中 WAM 推理慢的部署问题；mask 设计使训练和部署接口明确；真实机器人实验覆盖短程和长程任务；延迟优化给出实际部署数字。

## Weaknesses
贡献偏工程增量，依赖 GigaWorld-1 和内部数据；AutoResearch 更像训练流程自动化，科学贡献有限；任务和机器人平台仍较窄；未来视觉监督是否带来可解释世界模型能力没有深入验证。

## Future Work
作者没有展开很多未来方向，但自然延伸是更多机器人平台、更开放任务、更长时程任务，以及评估训练期视觉动力学监督对泛化和安全的贡献。

## Rating
创新度评分：3/5 - action-centered WAM 和 MoT 设计实用，但主要是已有 WAM 的系统性加速与强化。
相关度评分：3/3 (Core) - 直接面向机器人视频/动作世界模型。

## TL;DR
用训练时视频预测、部署时动作解码加速机器人WAM，增量但实用，值得精读。

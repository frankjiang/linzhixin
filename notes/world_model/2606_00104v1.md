# PEACE: A Planner-Executor Agent with Constraint Enforcement for UAVs

## Insight

无显著 insight。该工作的核心观察是：将 LLM 放在紧耦合控制回路中会带来延迟和幻觉风险，而将规划与执行解耦（单次 LLM 调用生成完整任务计划 + 确定性执行器调度）可以同时降低延迟、提高可审计性并支持独立的安全约束层。这一观察并不新颖，属于 LLM-based robotics 领域的工程常识。

## Motivation

**问题：** LLM 驱动的无人机系统存在三个瓶颈：(1) ReAct 式紧耦合调用导致高延迟和幻觉风险；(2) 端到端 VLA 策略不可解释、难以约束和审计；(3) 代码生成式方案需要逐任务重新验证安全性。

**同行做法：** VLN 模型（学习策略做导航）、VLA 模型（端到端像素到动作）、LLM 作为高层规划器/代码生成器（TypeFly、FlockGPT 等）。

**是否关键：** 对 UAV 部署场景有工程意义，但不构成学术上的关键问题。

## Method

- **Planner-Executor 架构：** 单次 LLM 调用将自然语言任务、机器人状态、世界模型历史转换为结构化 MissionPlan（推理 + tool call 序列），Executor 通过 ROS 2 tool-calling 接口顺序调度，仅在 tool 失败时触发有界重规划。
- **感知与 3D 定位：** 可插拔的 2D 检测器（YOLO / VLM）+ 针孔深度投影模块，将检测结果提升到 ENU 坐标系 3D 位置，并暴露深度可靠性标志。
- **世界模型服务：** 将检测流聚合为带时间戳的场景快照历史，规划时提供一致的世界状态上下文。
- **约束执行层：** 独立安全层在每条运动指令到达自驾仪前验证高度限制和水平地理围栏，违规时钳位或中止并触发重规划。
- **实验：** Gazebo/PX4 SITL 仿真，108 条自然语言 prompt，8 类任务。

创新程度较低，主要是系统集成层面的工程贡献。

## Experiment

- **实验方法：** 108 条 NL prompt 涵盖 8 类任务（起降、相对运动、高度控制、航点导航、几何路径跟随、目标搜索定位、开放词汇导航、复合多步任务、安全违规），定性分析行为模式和失败模式。
- **实验指标：** 无标准化定量指标，仅做定性行为分析（成功模式分类、失败模式分类）。
- **实验效果：** 度量类任务（航点、相对运动、高度控制）最可靠；感知依赖类任务受检测器召回率影响；识别出三类失败模式（规划器违规、感知不确定性、安全验证中止）。实验规模偏小，缺乏与 baseline 的定量对比。

## Value

**整体价值：** 工程系统论文，对 LLM-UAV 部署有参考价值，但学术贡献有限。

**对我们的启发：** 该工作中的「世界模型」仅是检测历史的聚合服务，与视频/3D/隐式世界模型研究方向无关。

**待解决问题：** 缺乏定量 benchmark 对比；开环规划在动态场景中脆弱；感知不确定性无恢复机制。

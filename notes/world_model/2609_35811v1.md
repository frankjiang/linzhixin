# Lookahead-R: Budget-Aware Tool Retrieval via Execution-Centric Planning

## Insight
API 工具检索中，文本语义相似不保证参数可用或调用及时；离线预测调用成功、时延和效用，再在预算内搜索，可能优于静态排序。作者用 ToolBench 消融支持该判断，但这里的“世界模型”是 API 执行代理，不涉及视觉或物理世界状态。

## Motivation
工具库规模增大后，纯文本检索容易选到不能执行的 API，逐个真实试调用又慢。论文要在检索质量与延迟之间取得折中；问题属于 LLM 代理和信息检索，与目标研究方向无实质关联。

## Method
先用稠密相似度与 BM25 粗召回；学生模型合成符合 API schema 的参数，在沙箱中试执行，用教师评分产生成功/错误、效用和时延记录；微调 Llama-3-8B 输出结构化模拟响应、风险、效用及时延桶。上线时用带成本与风险项的 MCTS 对候选工具作虚拟展开，超过预算的分支受罚。创新主要是把已知代理模型、成本信号与树搜索组合用于工具选择。

## Experiment
在 ToolBench 的 I1/I2/I3 工具检索划分上报告 NDCG@1/3/5、任务通过率、胜率、失败率和延迟。I3 NDCG@5 为 91.40%，ToolGen 为 90.16%；平均通过率 77.4%。I1 的 1000 问消融：完整模型成功率 78.5%、失败率 4.1%、平均延迟 680ms；去执行预测后为 61.5%、28.3%、1640ms；打乱成本标签后延迟 1120ms。文中“所有 NDCG 均优”表述与主表不符，例如 I1@5 为 89.80，低于 ToolGen 的 92.67。

## Value
若研究 LLM 工具代理可参考“模拟执行结果后按成本搜索”；对视频生成、3D 占据或 JEPA/Dreamer 世界模型几乎没有方法或评测借鉴价值。

## Strengths
把可执行性与实际延迟加入工具排序目标；有执行预测、成本和探索策略的机制消融。

## Weaknesses
世界模型并不建模环境时空演化，术语与用户研究方向不同。合成参数/教师评分与真实用户调用存在分布差，预算约束依赖代理成本预测；论文对主表结果有过度概括，且未报告可直接比较的视觉世界建模实验。

## Future Work
作者提出把这种预算规划接入端到端多步工具代理任务。

## Rating
创新度评分：1/5 - 就本研究方向而言无新技术贡献；在工具检索领域也主要是已有模块组合。
相关度评分：0/3 (Noise) - 纯 API/LLM 工具检索，未研究视频、3D 或隐式物理世界模型。

## TL;DR
用模拟API执行结果和成本约束树搜索改进工具检索，所谓世界模型仅指调用代理；视频与3D建模研究可跳过。

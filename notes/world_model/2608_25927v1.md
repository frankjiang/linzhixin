# Code World Model: Coding Agent as World Brain

## Insight

核心观察是：视频只记录世界规则执行后的可见结果，无法直接暴露规则、关系、离屏状态与跨长时间的因果后果；让视频模型同时承担规则推理、持久状态维护和视觉生成，学习低效且难以保证一致性。另一方面，语言模型适合稀疏而复杂的高层推理，却不适合逐帧执行碰撞、数值更新等高频操作。

由此论文推论，应将世界模型拆成三个角色：编码智能体负责低频决策并编写/修改规则，代码负责高频、确定且可复现的状态演化，视频模型只负责视觉实现。为了不把完整 3D 资产管线强加给编码智能体，作者进一步提出“最小充分”的 proxy：只显式传递位置、姿态、轨迹、遮挡与相机运动，把外观和细粒度动力学留给视频先验。

证据链目前只是可行性验证：编码智能体能基于现有游戏模板生成简单可执行世界；在约 5.6 小时 GTA V 配对数据上微调的 MiniMax-H3，能在若干定性案例中遵循 proxy 的人物位置、运动和镜头约束。不过论文没有验证长期因果后果是否真的持续，也没有用定量实验证明该分解优于端到端视频世界模型，因此 insight 有启发性，但尚未被完整证明。

## Motivation

现有交互视频世界模型大多把任务表述为动作、文本或相机条件下的下一段视频生成，并用视觉历史、检索帧或记忆模块缓解长程一致性问题。它们的核心状态仍主要藏在视频或隐变量中：不可见事件缺少记录，规则只能由稀疏视觉后果反推，超过上下文窗口的因果链尤其难学。

完整显式 3D 世界虽然可执行、空间约束强，却要求几何、资产、材质、动画与物理系统齐备，限制开放式内容和视觉上限。论文要解决的关键问题，是在“可执行、可持久的世界演化”与“开放、高保真的视觉生成”之间建立接口。这对开放式视频世界模型确属核心问题，但论文把问题定义得远大于当前实验覆盖范围。

## Method

- 编码智能体-代码循环：交互或事件到来后，智能体读取持久世界状态，调用已有机制或局部修改程序；代码执行位置、属性、碰撞、冷却、伤害、调度等高频更新；执行结果、测试和状态反馈再进入智能体。智能体推理频率、代码更新频率和视频生成帧率彼此解耦。
- 状态分解：完整状态由可执行状态与视觉状态组成。前者保存程序、实体属性、规则、关系和事件史，经智能体-代码转移更新；后者由视频模型根据新可执行状态和既有视觉状态生成。需要长期保持的视觉信息应重新写入持久状态，而不是只依赖视频上下文。
- 双通道条件：结构化文本描述身份、外观、动作语义等；proxy 保存当前观察必须遵守的相机、实体位置/朝向/尺度、场景布局、轨迹和交互状态。轻量确定性编译器把 capsule、wireframe、低多边形体或包围盒等可编程 primitive 光栅化为 proxy video，形成白盒的“状态到条件”路径。
- 条件带宽：proxy 空间分辨率为目标视频每边的四分之一，即单帧空间像素/视觉 token 量约为目标的 1/16；多模态编码器实际只采 11/124 帧。设计原则不是尽量重建目标，而是在编码智能体可构造性与空间约束强度间取“最小充分”带宽。
- 数据：游戏中同步记录 RGB 与运行时相机、实体、布局和关键交互状态，生成逐帧、实例对齐的 proxy-RGB 对；复杂物体退化为包围盒并由文本消歧。真实视频侧只在 KITTI-360 上演示离线构造：利用标定相机、语义 3D 重建和物体标注，经统一深度缓冲得到保持遮挡关系的 proxy，未用于本文主要训练结果。
- 训练：157 段、约 5.6 小时游戏视频被采成 9,420 个五秒片段。目标为 124 帧、1344×768、24 FPS；proxy 为 124 帧、336×192 的固定对数深度与语义 ID 图，编码器取其中 11 帧。对 MiniMax-H3 Ref2VA 的 50 个 Transformer block 做 rank-128 LoRA，共约 596M 可训练参数；8 张 H800、3 epoch/3,534 step。
- 推理：GPT-5.6 Sol 基于已有引擎控制、碰撞和更新模板搭建简单世界；GPT Image 2 另生成首帧外观锚点，随后视频模型用文本和完整 proxy 序列生成 124 帧。长视频以 34 帧重叠、每窗前进 90 帧拼接，并反复注入同一外观锚点。

创新主要在系统分工与 proxy 接口，而非新的视频生成骨干。它把“代码世界模型”和“视频世界模型”组合成较清晰的可执行架构，但当前实现尚未形成论文愿景中的完整闭环。

## Experiment

实验只做了定性可行性评估，没有定义数值指标、测试集规模、人工评分协议、消融或统计显著性。

- 图 3 展示游戏与 KITTI-360 的 RGB-proxy 对齐样例，说明 proxy 可由引擎状态或离线几何重建编译。
- 图 4 给出 5 个跨角色、场景风格、动作和相机轨迹的生成案例；每例展示 6 个时间点的 proxy 与 RGB。视觉上，人物数量、粗位置、镜头运动和主要轨迹大体受控，同时保留了丰富外观。
- 作者称项目页视频相比动作/相机条件模型具有更精细、响应更快的控制，但正文没有统一基线、定量控制误差或盲评；比较还明确忽略推理延迟。
- 没有验证编码智能体维护长期世界状态的能力，没有离屏事件、规则修改、复杂多实体因果链或用户长期交互实验；也没有 text-only、不同 proxy 带宽、无首帧锚点等关键消融。

因此实验只能支持“proxy 可被视频模型学习并用于粗粒度时空控制”，不能支持“已构建开放式、长期一致的 Code World Model”。

## Value

论文最有价值之处是把世界演化与视觉实现明确解耦，并把 code 视为可测试、可修改的持久记忆与动力学执行介质。这为视频世界模型补充显式状态、规则和离屏演化提供了清晰架构，也提示可把 proxy 作为按需启用的视觉提示，而非最终 3D 世界。

对研究的直接启发包括：把执行日志和状态变化作为视频训练条件；研究 proxy 的信息带宽与可构造性；用规则测试、状态一致性和视觉控制误差共同评估世界模型。待解决的核心问题仍是状态-视觉双向闭环、生成观察与代码状态不一致时的校正、长期身份/外观持久性、实时推理，以及复杂机制的自主生成与验证。

## Strengths

- 对视频世界模型“只看结果、不见规则”的瓶颈分析清晰，系统分工有直接解释力。
- proxy 是可寻址、可编辑、可追溯到世界状态的白盒条件，比纯文本更精确、比完整 3D 资产更轻。
- 游戏数据能够天然获得逐帧实例对应；真实数据构造方案也考虑了相机、深度与遮挡对齐。
- 训练与推理配置披露较完整，且主动说明计算、实时性和编码智能体能力边界。

## Weaknesses

- 论文的核心主张远强于证据：没有定量指标、正式基线、消融或统计分析，主要依据精选可视化。
- 没有端到端展示“事件-代码修改-持久状态演化-proxy-视频反馈”的长期交互闭环；编码智能体只在现有 AAA 场景和逻辑模板上搭建简单世界。
- GPT Image 2 首帧锚点以及重叠窗口反复注入锚点是重要外部能力与混杂因素，论文未衡量 proxy 本身的贡献。
- 所谓逐帧 proxy 在多模态编码器中实际只采 11 帧；快速或细粒度动作的控制上限未评估。
- 真实视频部分只是 KITTI-360 配对构造 proof of concept，没有训练或迁移结果。
- 视觉生成与可执行状态可能发生冲突，但系统缺少视觉观测回写、状态校准和失败检测机制。
- 596M 可训练参数、H800 推理和非实时窗口生成与“可交互世界”目标仍有明显距离。

## Future Work

作者明确提出扩大配对数据和训练计算，提升生成质量并实现自回归实时生成；让未来编码智能体从零设计、实现、测试和维护更复杂的游戏机制，最终自主构建完整开放世界；让智能体按任务自动启停 proxy，并选择实体、区域、状态类型、分辨率和条件帧率，动态调节条件带宽。结合本文暴露的缺口，真实视频 proxy 的大规模训练、复杂长期交互和完整状态-视觉反馈闭环也值得继续研究。

## Rating

创新度评分：3/5 - 编码智能体、可执行持久状态与 proxy 视频接口的组合有明确新意，但生成骨干沿用现有模型，且证据仅为小规模定性原型。
相关度评分：3/3 (Core) - 直接研究开放式交互视频世界模型，并涉及显式 3D proxy、长期状态和视频条件生成。

## TL;DR

以编码智能体和可执行状态统筹世界演化，再用代理视频驱动视觉渲染；概念新但验证初步，值得精读。

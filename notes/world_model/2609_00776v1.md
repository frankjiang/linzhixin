# Solaris: Towards Interfaces That Are Generated, Not Coded

## Insight

观察：把复杂视觉界面先翻译成 HTML/CSS 等中间表示，会随视觉复杂度上升持续丢失外观信息；论文的 30 个界面重建实验中，DINOv3、CLIP 和 SSIM 曲线从普通网页到自然图像均明显下降。推论：若视觉帧本身就是应用状态，并由动作条件视频模型直接生成下一帧，就可绕过“视觉→代码→视觉”的瓶颈，同时让行为不再受预编码工作流限制。Solaris 以 LLM 解释意图、视觉世界模型连续渲染来实现这一分工；与 Claude Opus 5 代码界面的用户对比中，Solaris 在指令遵循和自然行为上分别获 62% 与 72% 偏好，为推论提供感知层证据，但尚未证明功能正确性或长时状态可靠性。

## Motivation

传统应用必须把设计翻译成代码，外观会被离散组件近似，所有行为也需预先实现；单张生成图虽视觉丰富，却不可运行。已有 NeuralOS、ViMo、CUWM 等 GUI 世界模型主要复现既有软件，其交互仍受参考实现约束。Solaris 试图让模型同时生成界面外观和行为，使同一场景可按上下文解释点击、拖拽或输入。核心工程问题是亚秒级响应、长会话一致性和逐帧生成成本，方向重要且具有新的软件/智能体环境想象空间。

## Method

- 以 Runway Gen-4.5 视频生成模型为基座，沿用 GWM-1 的世界模型路线；把点击、拖拽、键盘输入等用户动作作为逐帧生成条件，模型只看到已发生的交互并自回归预测后续帧。
- 实时化分三步：把整段视频生成改为前缀依赖的自回归逐帧生成；把数十步扩散蒸馏为少数去噪步；再用快速模型自己的输出训练，以缓解长交互中的误差累积和画质漂移。
- LLM 保存会话语境并解释用户意图，决定是局部修改还是场景切换、定义对象行为并生成渲染提示；视觉世界模型负责把该意图连续渲染为画面，实现“推理/渲染”分离。
- 用户给出初始视觉状态，系统持续流式生成；交互含义由自然语言指定，不依赖预定义页面、模板或控件。因而同一拖拽可依上下文表示缩放、测量或移动对象。
- 论文未披露训练数据、参数量、动作编码、蒸馏目标与步数、自回归上下文长度、帧率/延迟或硬件，方法只能理解到系统设计层，无法复现。

## Experiment

- “代码翻译成本”实验覆盖 30 个界面，类别从普通网页、幻灯片、图形设计到自然图像；比较 GPT-4o、Gemini 2.5 Pro、Claude Fable 5 从单截图生成代码后的重建。以就地结构相似度 SSIM、区域最佳匹配的 DINOv3 特征相似度以及图中报告的 CLIP 相似度衡量；所有模型随复杂度上升退化，自然图像最明显，但正文未给完整数值表或显著性检验。
- Solaris 与 Claude Opus 5 代码实现从相同初图接收相同交互请求。250 名参与者、30 个交互样例、近 7,500 次成对判断中，指令遵循偏好为 Solaris 62%、代码结果 25%、相同 13%；场景内自然性为 72%、21%、相同 7%。
- 论文展示试衣、室内设计、沙拉制作、燃烧教学、场景导航、产品探索等开放交互可视化，支持其适用范围，但没有成功率、视觉质量、动作延迟、吞吐、成本或跨步一致性指标。
- 没有模型/训练组件消融，也没有与 NeuralOS、ViMo、GWM-1 等生成式界面模型进行同协议比较；用户研究只比较一种代码基线。

## Value

Solaris 把 GUI 明确建模为动作条件的连续视觉世界，提出“界面直接生成而非编码”的有吸引力范式；其 LLM 状态管理与实时视觉渲染分工，也可迁移到交互式视频世界模型和多样化智能体训练环境。遗憾的是论文更接近产品概念/系统报告：核心模型、数据和速度均不透明，实验主要验证审美与自然感，尚不能说明它能作为可靠、可复现、可执行的软件环境。

## Strengths

- 直接挑战“界面必须有代码中间表示”的假设，问题设定新颖且展示场景丰富。
- 同时考虑自回归、少步蒸馏和自生成数据训练，对实时性与 rollout 漂移给出一致的工程方案。
- LLM 负责语义状态、视频模型负责渲染的分层清楚，支持上下文相关且开放的动作语义。
- 250 人、近 7,500 次判断的用户研究给出了明确偏好差异，而非只展示精选样例。

## Weaknesses

- 缺少几乎所有可复现细节，尤其没有实际 fps、端到端延迟、硬件、成本和最长稳定会话长度；“实时”“数量级降本”无法核验。
- 用户偏好只衡量指令观感和自然性，不检查按钮/文本/购物车等状态是否真实、持久且可执行，也未报告参与者分配、置信区间或统计检验。
- 与代码界面的比较存在模态和能力混杂：Claude Opus 5 的单次代码生成并非专门的交互式 GUI 系统，不能单独证明像素生成优于代码。
- 无架构/训练消融、无强 GUI 世界模型基准；重建实验论证代码信息瓶颈，却没有直接量化 Solaris 对原始状态的保持程度。
- 文本稳定性、事实可信度、长会话一致性、无障碍和软件栈集成都尚未解决；生成画面也缺乏传统程序的确定性和可验证状态。

## Future Work

作者明确把以下方向列为重点：用参考图、产品数据和文档等经验证上下文增强事实锚定；提高长会话的视觉/语义一致性；解决实时可读文本；与屏幕阅读器和无障碍 API 等软件基础设施集成；继续探索更丰富交互、更强 grounding 和长期运行体验，并与合作方公开发布。

## Rating

创新度评分：3/5 - “生成界面即应用”的系统设定和开放交互展示有明显概念创新，但技术组件大多沿用视频模型实时化套路，且披露与验证不足以支撑更高评分。

相关度评分：3/3 (Core) - 本质是由用户动作条件驱动、实时自回归生成视觉帧的视频世界模型，只是世界被限定为 GUI/视觉界面，仍直接属于视频世界模型研究。

## TL;DR

将 GUI 逐帧生成并由 LLM 解释交互，展示无代码界面世界模型；方向大胆但技术细节与评测不足，可选读。

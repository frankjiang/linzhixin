# AutoGUIWorld: Image Generators as Visual World Models for GUI Agent

## Insight
GUI 策略只观察截图，因而可尝试在观测层合成「动作后画面」，无需运行每个专业软件。作者发现，把任务规划中的预期局部变化交给通用图像编辑器逐步渲染，并给动作落点与转移做质检，合成轨迹能迁移到真实软件任务：OSWorld 从 33.0% 到 40.8%，ScienceBoard 从 14.0% 到 32.2%。这是训练数据效用的经验支持，不等于生成器学到了软件的真实隐藏状态或因果转移。

## Motivation
GUI 代理需要跨平台、专业应用与长工作流的动作轨迹；人工示范、自动探索和录屏抽取受可安装软件与可访问状态限制。纯生成截图又容易出现不对应动作的画面、内容漂移和错误坐标。问题属于 GUI 数据合成，借鉴点是免环境 rollout 和转移保真度控制，与物理视频世界模型距离较远。

## Method
先采样 OS 约束、视觉风格及初始窗口/页面状态，由预训练 Image2 渲染种子截图；再据种子生成任务，由 Meta Planner 列出原子动作、目标元素和预期视觉变化。Voyager 每步读取当前截图、动作和进度，写出下一屏编辑提示，Image2 以上一屏为参考生成下一屏，构成长轨迹；LocateAnything 在动作前截图定位目标框，转换成 0–999 坐标。Gemini 质检分别判目标存在/落框、动作有效和前后屏变化是否符合动作；可修复框重新定位，其余缺陷过滤。生成 84,373 条、最终保留 79,266 条单步监督样本，在同一截图式工具调用格式上微调 Qwen3.5-35B-A3B。这里的编辑模型同时收到规划器写明的「应发生什么」，不是仅由动作自行推断环境转移。

## Experiment
OSWorld 361 任务平均分 33.0→40.8，Windows Agent Arena 154 任务 19.4→27.9；macOSWorld 231 任务成功率 28.1→45.0，ScienceBoard 非 Lean 的 143 任务 14.0→32.2。ScreenSpot-Pro 1,581 个正例定位准确率 31.7→57.1%，文字 41.2→72.0%、图标 16.2→32.9%。Chrome 在 OSWorld 39.0→26.0%、WAA 11.2→0.0%，说明迁移并不均匀。相对 35 万 AgentNet 真人样本训练曲线，8 万合成样本终点更好，但两者推理 thinking 设置不同，不能视为公平的数据来源消融。Qwen 视觉特征 MMD 的合成/真实跨源距离比为 0.59–1.24，来源分类 AUC 仍接近 1。桌面 42,526 个可审转移经 VLM 标出 3.04% 动作图像不一致；先排无效动作/落点后为 818/39,351（2.08%），拖拽、滚动和文字输入分别仍有 7.58%、7.09%、6.35% 的错误。

## Value
对视频世界模型的数据生成流程可选读：把「动作意图规划、局部视觉变更、空间标注、逐步质检」拆开，适合借鉴于合成交互轨迹。其主要结果检验的是 GUI 代理微调收益，并未验证物理、3D、长期隐藏状态一致性。

## Strengths
跨四平台构造较大训练集，真实执行、精细定位和专业软件都做下游评测；公开工具格式、提示模板及质检规则。附录展示命令被替换、输入文字被重写、滚动/拖拽无效和持久内容突变等具体失败，而不只展示成功截图。

## Weaknesses
无独立消融量化规划器、Image2、落点修复及质检的各自贡献；未与相同预算、相同推理设置的真实数据比较。转移错误率来自单一 VLM 判别器，未测其与人评的一致性，Chrome 的中间过滤量按桌面留存率推断。截图可以显示文件已保存等「成功」但没有真实文件系统/DOM，单步质量检查也不能证明长轨迹可执行；C2ST 仍容易分辨合成来源。正文提及 CAD/3D 是软件界面场景，未构建 3D 世界状态。

## Future Work
作者建议用特定软件的真实交互训练垂直 GUI 世界模型，提升操作规则与长时状态一致性；当前图像编辑对精确文本、拖拽、滚动和持久内容的动作保真仍需改进。

## Rating
创新度评分：2/5 - 预训练图像编辑器加规划与质检形成有效 GUI 数据工程，但没有新的视频/3D/隐式世界模型技术。
相关度评分：1/3 (Tangential) - 仅合成动作条件视觉轨迹的方法可间接迁移，研究对象是 GUI 而非用户关注的物理视频、3D 或 JEPA/Dreamer 世界模型。

## TL;DR
用规划器与图像编辑合成免部署的GUI交互轨迹，提升真实软件代理但不建模物理状态；做数据合成者可选读。

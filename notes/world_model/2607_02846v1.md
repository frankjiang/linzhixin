# Object-Centric Environment Modeling for Agentic Tasks

## Insight
论文的 insight 是：语言 agent 的环境模型可以不只是自然语言记忆，而是可执行的 object-centric Python code。对象类、实体状态和过程知识被写进代码库后，agent 可以通过执行和导入来检查世界模型一致性。

## Motivation
LLM agent 在长任务中容易忘记对象属性、环境机制和程序步骤。纯文本 memory 难以验证，也难以组合。作者希望把经验转化为结构化、可复用、可执行的对象知识。

## Method
OCM 维护两个代码库：object knowledge 存储对象类、实体和机制；procedure knowledge 存储可导入对象类的任务过程。每轮 episode 后，系统更新两类代码，并执行程序验证一致性。推理时使用 progressive knowledge disclosure，先看签名，需要时再读源码。

## Experiment
实验覆盖 ScienceWorld、ALFWorld 和 PlanCraft。OCM 在平均 rank、成功率和无效动作数量上优于若干 memory/planning baseline，尤其在需要复用对象机制的任务中更稳。

## Value
对世界模型广义概念有参考，但和用户关注的视频、3D、JEPA/Dreamer 关系较弱。它更像 LLM agent 的符号环境记忆系统。

## Strengths
对象中心表示清楚；可执行代码带来一定验证能力；对文本环境 agent 有实用价值。

## Weaknesses
限于文本/符号环境；对象边界和 action schema 相对稳定；代码执行只能验证语法/部分一致性，不保证真实环境语义正确。

## Future Work
未来可扩展到多模态动态环境、自动对象抽象和更严格的语义验证。

## Rating
创新度评分：2/5 - object-centric code memory 有工程价值，但不是新型世界模型。
相关度评分：1/3 (Tangential) - 属于 LLM agent 环境模型，和视频/3D/隐式世界模型关联很弱。

## TL;DR
OCM 用可执行对象代码维护 LLM agent 环境模型，非视频/机器人核心，可跳过。

# Coding Agent Is Good As World Simulator

创新度：3/5 | 相关度：2/3

## Insight

**核心 Insight：** 视频世界模型在隐式潜在空间中学到的动力学并不显式满足物理约束，导致生成的视频出现不稳定接触、形状扭曲、运动不一致等物理不合理现象。与其让神经网络隐式学习物理规律，不如让 coding agent 直接生成可执行的物理仿真代码——生成的代码本身就是世界的显式表示（几何体、关节、接触、材质、数值参数），物理引擎的执行天然保证物理一致性。

**推论：** 「代码即世界模型」——将世界建模问题从帧预测转化为仿真代码生成，可以获得可检查、可修复、物理一致的世界模拟。

**证明：** 在 WorldModelBench 上与 Wan2.2-T2V-5B 对比，多智能体框架在 Instruction Following 上显著优于视频生成基线（p=0.000059），在 FSI 场景上总分显著更高（p=0.0012）。

## Motivation

**问题：** 视频世界模型生成的 rollout 缺乏物理准确性——接触不稳定、穿透、形状变形、运动不一致。根本原因是这些模型在隐式潜在空间中表示动力学，不显式执行物理约束。

**同行做法：** 潜在世界模型（Dreamer 等）支持规划控制但不生成可视内容；视频生成模型（Sora、Wan 等）生成视觉逼真的视频但不保证物理准确性；场景生成方法（SceneCraft 等）生成 3D 场景但不构建可运行的仿真。

**是否关键：** 提出了一个有趣的视角——物理世界模型的表示形式问题，但「代码即世界模型」的方案依赖物理引擎和 3D 资产，适用范围有限。

## Method

**整体管线：** 多智能体闭环框架，将自然语言 prompt（+ 可选参考图像）转化为可执行的 PyChrono 仿真程序。

1. **Plan Agent：** 将 NL prompt 转换为结构化仿真计划（物体列表、拓扑谓词、物理角色、相机配置、实现步骤）。支持 Asset Extraction（识别物理实体）、Scene Inference（用拓扑谓词编码空间关系，而非直接指定坐标）、用户交互确认。
2. **Code Agent：** 基于三类仿真特定知识生成 PyChrono 代码：Skill Library（仿真模式片段）、Tool Interface（确定性操作工具）、API 索引（版本特定 API 验证）。
3. **执行与审查循环：** 代码在隔离进程中执行，Visual Review Agent（VLM）描述仿真视频的视觉一致性，Physics Analysis Agent 检查物理诊断日志（轨迹、接触、求解器警告），Simulation Judge 综合判断并生成结构化错误报告，反馈给 Code Agent 迭代修复。
4. **资产系统：** 外部 3D 资产 + Chrono 原生资产，统一管理；使用 CoACD 算法将复杂 mesh 分解为凸包用于碰撞检测。

**创新程度：** 中等偏上。「代码即世界模型」的视角有新意，多智能体仿真生成框架的系统设计较为完整，但核心还是 LLM 代码生成 + 物理引擎的组合，依赖已有物理引擎能力。

## Experiment

**实验方法：**
- 与 Wan2.2-T2V-5B 视频生成基线对比，使用 WorldModelBench 评估。
- 三个场景：室内机器人（Go2 办公室行走）、户外车辆（HMMWV 越野驾驶）、流固耦合（Polaris 车辆过浮桥）。
- 每场景 10 次配对运行，paired t-test。

**实验指标：**
- WorldModelBench 三轴：Instruction Following (0-3)、Physics Adherence (0-5)、Commonsense (0-2)。
- Gemini-3.1-pro-preview 作为评判 LLM。

**实验效果：**
- FSI 场景总分 6.80 vs 5.10（p=0.0012），显著优于视频基线。
- Instruction Following 聚合分 5.90 vs 3.50（p=0.000059），显著提升。
- Physics Adherence 和 Commonsense 差异不显著。
- 时间/token 开销大：单次成功运行 24-30 分钟，百万级 token。
- 评估规模小（3 场景），结论初步。

## Value

**整体价值：** 提出了一个有趣的替代范式——用代码生成+物理引擎替代端到端视频生成来做世界模拟。这种方式在物理准确性和可检查性上有天然优势，但在视觉多样性、开放世界泛化、实时性上受限于资产库和引擎能力。

**对我们的启发：**
1. 「显式物理 vs 隐式学习」是世界模型设计的核心权衡——该工作清晰地暴露了视频世界模型在物理准确性上的短板。
2. 对于需要物理精度的仿真/embodied AI 场景，代码生成+物理引擎可能是比视频生成更合适的世界模拟方案。
3. 多智能体代码生成+执行反馈的闭环设计模式可参考。

**待解决问题：** 资产库有限导致开放世界泛化受限；token 开销极高（百万级）；修复过程不保证单调收敛；仅评估了 3 个场景。

## TL;DR

提出「代码即世界模型」范式，用多智能体框架生成可执行物理仿真代码替代视频生成，物理准确性显著优于视频基线但泛化受限。可选读。

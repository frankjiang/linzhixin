# VideoTok4D: A 4D-Aware Video Tokenizer for Compact World Representation

> 阅读范围：PDF 全部 9 页；重点核对方法、表 1–5 与生成协议。

## Insight

观察：场景外观/几何分布广，而物体运动稀疏且混有相机运动；固定网格的时序注意力容易聚合不同物体。推论：静态内容与沿轨迹对齐的动态内容应分别压缩，再共享给各视角。等容量消融和冻结 token 的轨迹解码支持这种分工，但只证明互补偏置，未证明严格解耦或物理状态可辨识。

## Motivation

普通视频 tokenizer 压缩的是观测序列，静态 3D tokenizer 又缺乏动态表达；显式 4D 高斯表示通常占用较大。论文解决“用小型共享状态表示同一动态事件，并从不同相机重放”的关键表示问题，尚未涉及动作驱动的未来推演。

## Method

1. 输入 32 帧视频和已标定相机轨迹；冻结 VA-VAE 提取逐帧特征。空间分支加入相机射线编码，以查询注意力生成 1,024 个静态 token。
2. RAFT 光流减去 UniDepth 深度与相机位姿计算的静态场景光流，阈值化得到运动掩码；动态区域先做空间注意力，再沿光流轨迹做时序注意力，聚合成 512 个动态 token。每个 token 64 维。
3. 相机条件 rectified-flow 解码器生成目标视频 latent，再由冻结 VideoDCAE 解码为 RGB；以新视角视频监督学习表示。
4. Co4DGen 在联合 token 空间训练条件扩散先验：静态查询仅读静态流，动态查询可读两者。一次采样共享状态，针对九条目标轨迹分别解码。

创新主要是将静动态分解、相机补偿和轨迹注意力组合进可生成的 4D tokenizer，构件本身并非全新。

## Experiment

- **协议**：MultiCamVideo 的 13,600 个动态场景，400 个测试场景与训练资产不重叠；32 帧、256×256。SceneTok/SceneGen 做容量匹配，DFoT 同数据重训；未与使用大规模外部预训练的全部生成系统直接比较。
- **重建，表 1**：PSNR 20.22、SSIM 0.68、LPIPS 0.23、rFVD 185.57；匹配的 SceneTok 为 17.67、0.50、0.32、247.41。图示呈现更清楚的肢体和较少重影。
- **存储口径**：98.30K 个 FP32 数值，对比 MoVieS 的 948.93M，约缩小 9,650 倍；不计共享网络，且 MoVieS 按全部时间戳展开。不能解释成系统总内存降低四个数量级。
- **生成，表 2**：九视角合计 119.18 秒，DFoT 405.60 秒、SceneGen 124.24 秒；gFVD 分别 224.94、342.86、296.69。另报 gFID、跨视角 FVD/CLIP 相似度和运动平滑度；共享 token 仍需逐视角解码。
- **消融，表 3–5**：去分解/运动隔离/轨迹注意力后 PSNR 为 17.78/18.82/18.11；混合轨迹 EPE 从最佳单组的 0.445 降到联合表示的 0.240。

## Value

适合借鉴“共享动态场景状态＋按相机查询”的表示接口，以及用轨迹探针检验 token 是否保存运动信息。要成为交互世界模型，还需学习动作条件状态转移，并检验未观测时间的预测能力。

## Strengths

- 同时报告表示体积、重建质量、多视角生成成本，收益口径相对清楚。
- 等 token 预算消融及分组探针支持核心设计，未将静动态分工包装成完全解耦。

## Weaknesses

- 仅单一数据集和短片段；依赖标定、单目深度与光流，遮挡和估计误差的鲁棒性未充分验证。
- 缺少真实几何、物理正确性、长期状态保持与动作干预评估；视觉一致性不足以证明世界动力学。
- 固定 token 预算对更长视频、更复杂运动的扩展性，以及非对称先验注意力的独立贡献仍不清楚。

## Future Work

作者未明确列出未来改进计划。长期扩展、无标定输入和动作条件预测属于本笔记提出的后续问题。

## Rating

创新度评分：3/5 - 将已有表示与对齐机制组织成有效的紧凑 4D 管线，实验支持充分，但未建立新的动力学建模范式。

相关度评分：3/3 (Core) - 直接研究视频到隐式动态 3D/4D 表示及跨视角生成。

## TL;DR

以静动态分离和轨迹注意力压缩四维场景，一次采样支持多视角重放，值得精读表示设计。

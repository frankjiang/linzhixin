# MASS: Multiplayer World Models with Authoritative Shared State

## Insight
观察到多人世界中“世界动力学状态”应属于环境而非任一相机；若每个视角都维护递归视觉 latent，同一实体会被重复计算且不同视角可相互矛盾。作者据传统游戏服务器架构推论：学习一个唯一、显式、带类型的 authoritative state 作为递归记忆和同步对象，再按需从同一状态渲染各视角，可令状态更新成本与视角数解耦，并从构造上保证跨视角状态一致。匹配的多人 Snake 实验中，MASS 的状态恢复为 0.764、跨视角分歧为 0，而最佳视频基线分别仅 0.128 和 1.000，支持该推论。

## Motivation
现有 GameNGen、Oasis、DIAMOND、MultiWorld 等以像素或视觉 latent 同时承载状态和显示，适合单人，却难扩展到上千玩家：计算重复、视图漂移且不能直接验证实体状态。MASS 要解决的是多人 learned simulator 的状态所有权、同步和可扩展性问题。该问题对大规模交互世界重要，但论文将视觉世界模型的开放状态学习，改写为可访问完整引擎状态的结构化转移学习，适用前提较强。

## Method
每个游戏提供声明式 schema，定义实体种类、字段、数量、合法值、固定槽位与局部空间上下文。World State Tokenizer 将全局量、玩家、物体等变成规范化 typed records；宽 256、6 层、8 头的 decoder-only Transformer（匹配实验约 5.66M 参数）逐 record 自回归预测下一状态，字段 mask 和确定性 selector 保证类型、排序、唯一性等结构约束。记录间无 attention，交互仅由当前状态的局部邻域窗口传入，因此可批量更新 5,121 个 records。随后相机投影器把共享状态转成 16 通道局部语义张量，残差 U-Net 生成 RGB。服务器每 tick 只运行一次 Logic Engine、发布版本化状态；客户端可从最新快照本地续推以跨过网络中断。

创新点在于把传统 authoritative-server 合约显式引入 learned world model，并将可测逻辑与渲染分层；Transformer、U-Net、类型 mask 本身较常规。不同游戏共享架构和接口，但 tokenizer、schema、权重和 renderer 均需分别构建/训练。

## Experiment
核心 matched Snake benchmark 固定训练轨迹、动作、相机与优化预算，测试 128 tick、两个同步视角；比较官方 MultiWorld、独立 per-view 视频预测 B-PV、共享视觉 latent B-SL、dense joint-state U-Net B-UN。指标含 LPIPS、冻结 parser 的状态/计数/位置/事件恢复、跨视角分歧 X-view、结构无效率，以及直接 typed-state 指标。MASS 在七项中领先六项：LPIPS 0.098、Parser 0.764、Event F1 0.552、X-view 0；但 Invalid 为 0.177，逊于 B-PV/B-SL 的 0.052。直接状态预测 H=1/32/128 的位置准确率为 99.1%/90.2%/72.3%，结构矛盾率始终 0；128 tick 的完整状态 exact 已为 0。

跨游戏测试覆盖 Snake、Crate Pusher、Pac-Man、Breakout、Tile Merger，以及八种渲染主题。Breakout H=128 active-token accuracy 85.7%、full exact 3.2%；Tile Merger 为 72.5% 和 0。长时无参考 stress test 可结构合法地运行到 4,096 tick，但 277–306 个不同状态后进入周期吸引子。规模实验在 1,024 玩家、4,096 food buckets 上推进 10,000 tick；固定状态下 1 到 1,024 个视图的渲染时间由 189.6 ms 增至 842.4 ms。客户端缺 1–8 次服务器更新时，本地头像位置保持准确，但仅知本地动作时可见状态 IoU 从 0.815 降至 0.429。SRSC 用 Qwen3.5-27B 分解逻辑与渲染误差，显示长时退化主要来自 Logic Engine。

## Value
论文清楚展示“可审计的共享实体状态”能解决多视图一致性和同步问题，对多人视频世界、3D 场景图/对象中心世界模型具有架构启发：逻辑状态应是视图无关、可版本化的第一等接口。但当前更像学习替代规则引擎的神经游戏服务器，而非从视频学习通用世界；完整真值状态、schema 和外生随机量均由引擎提供，因而不能直接迁移到真实视频或未知 3D 环境。

## Strengths
- 问题定义和系统抽象鲜明，world update 与 view rendering 的分离具有工程与建模意义。
- 匹配基线、直接状态指标、跨视图指标及逻辑/渲染误差分解较完整，避免只看 LPIPS。
- 5.66M 结构化模型对比 5.60B MultiWorld 仍显著领先，说明表示选择比模型规模更关键。
- 附录详细披露 codec、数据切分、训练、长时吸引子和客户端缺包协议，可复现性较好。

## Weaknesses
- 训练和推理都要求游戏暴露完整 typed state、persistent slots、schema、相机投影及记录的外生随机量；这回避了从视觉推断隐藏状态的核心难题。
- 跨游戏仅复用架构，不共享权重；每个游戏仍需人工 schema/tokenizer、专属数据和 renderer，因此“general”程度有限。
- 跨视角分歧为 0 很大程度由“同一状态+确定投影”结构保证，并非学习出的跨视图能力。
- 关键对比集中在简单 2D Snake，B-UN 的位置表现异常接近 0，尚缺对象中心、图网络或 slot-based 强结构化基线。
- record 间只看手工局部窗口，远程/全局交互表达受限；大规模逻辑单步耗时仍高，客户端测试没有完整网络系统评估。
- 长时结构合法不等于动力学正确：Snake 很快进入循环，Crate Pusher 的 SRSC 在 H=100 已降到 10。

## Future Work
作者明确提出将该原则扩展到 3D 环境与更丰富实体交互。还需要研究从图像/多视图自动发现 schema 和实体状态、跨游戏共享动力学、随机多模态转移、全局交互建模，以及与真实网络延迟和状态压缩结合。

## Rating
创新度评分：3/5 - authoritative typed state 与学习渲染分离的系统化方案有明确新意和扎实验证，但高度依赖人工结构与引擎真值，实验仍以简单 2D 游戏为主。
相关度评分：2/3 (Related) - 属于交互式世界模型并对多视图/多人一致性有直接借鉴价值，但不是视频生成、3D 或 JEPA/Dreamer 式隐式世界模型的核心研究。

## TL;DR
用唯一 typed state 分离多人世界逻辑与视图渲染，架构启发强但依赖引擎真值，可选读。

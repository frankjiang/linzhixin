# Generative World Renderer at the Speed of Play

## Insight
核心 insight 是把交互世界拆成“引擎负责结构/动力学，生成模型负责外观渲染”。作者观察到纯生成式世界模型难以在实时交互中同时保持几何、物理和一致性，于是用 G-buffer 条件把 world state 固定在游戏/物理引擎中，让 diffusion renderer 只做可控 RGB shading。

## Motivation
实时游戏级生成渲染需要低延迟、高一致性、prompt 风格可控和流式长序列。已有视频扩散渲染器质量高但离线、双向窗口、步数多，不能边玩边生成；纯视频世界模型又容易破坏玩法和几何。本文解决的是实时 generative rendering，不是完整 learned dynamics world model。

## Method
AlayaRenderer-Flash 从 G-buffer 输入生成 RGB，条件包括 albedo、depth、normal、roughness、metallic 和 text。方法把原 50-step bidirectional fixed window AlayaRenderer 改成 chunk-level autoregressive streaming，每个 chunk 4 个 latent frames；使用多级历史压缩、初始 latent frame 作为 appearance anchor、persistent text sink KV、causal encoder/decoder cache。加速上用 CFG guidance distillation、32/16/8/4 progressive distillation、Mean Flow Distillation self-rollout、小 GAN heads，以及 tiny G-buffer encoder 和 tiny temporal decoder。

## Experiment
数据来自 Black Myth Wukong，1352 train、131 test，30 FPS，输入 832x448。指标包括 SCLIP-I、tLPIPSwarp、Boundary MSE/SSIM、MCLIP、FPS 和 VRAM。原 50-step 模型 0.56 FPS、30.1GB；AR 50-step 1.53 FPS；AR-distilled 4-step 6.30 FPS；Flash 达到 SCLIP 0.847、FVD 384.1、tLPIPS 0.155、31.54 FPS、16.2GB。外部 baseline 中 DiffusionRenderer 离线质量略高但仅 1.10 FPS；Flash 可在 SuperTuxKart 部署中含引擎读回和显示维持 30 FPS。

## Value
对实时交互世界系统很有启发：如果场景状态、碰撞和相机都由引擎保证，生成模型可以专注渲染并显著降低可控性难度。对视频世界模型方向是相关但非核心，因为它没有学习动作到世界状态的动力学。

## Strengths
系统目标清晰，实时性能非常强；G-buffer 条件让结构可控；蒸馏和 codec 工程细节完整；有实际游戏引擎部署。

## Weaknesses
不解决 learned dynamics 或 object state transition；依赖已有引擎与高质量 G-buffer；数据集域较窄；评价主要是渲染质量和时序一致性，不是世界理解。

## Future Work
作者未给出细粒度计划，但把它定位为通向实时 generative world model 的一步；自然方向是更广泛游戏/真实场景、更低硬件成本和更强动态 prompt 控制。

## Rating
创新度评分：3/5 - 实时流式渲染系统很强，但主要是现有扩散渲染器的工程化和蒸馏。
相关度评分：2/3 (Related) - 与交互式世界生成和视频渲染相关，但不学习完整世界动力学。

# Stateful Worlds, Stateless Elasticity: Exact-State Serving for Interactive World Models

## Insight
核心 insight 是：交互式世界模型的“状态”主要是 GPU 上多 GB attention/cache tensor，若要无缝迁移会话，不能用常见的丢弃、量化或近似压缩替代，必须 bit-exact 搬迁 live state。否则生成轨迹会立即分叉，用户的 worldline 断裂。

## Motivation
交互式 world model 服务需要弹性调度、负载均衡和故障迁移，但每个会话包含巨大的隐式历史状态。传统无状态 serving、KV cache eviction 或 approximate state transfer 无法保证世界连续性。论文解决的是部署层面的“精确状态迁移”问题。

## Method
作者提出 WorldMove/Worldline 抽象：用六个迁移原语、fail-closed commit 和 CRC receipt verification，把会话 state 在 GPU/节点间迁移。核心 admissibility 条件是迁移必须在 readout horizon 内完成，且网络带宽要覆盖 state size/horizon 加上 dirty rate。论文还分析 dirty tensor、move gate、incast admission 和 lossless GPU codec。

## Experiment
以 Matrix-Game 2.0 测量：每会话 state 5.32GB，可迁移子集 1.67GB，dirty rate 0.93GB/s。同机迁移 18.8ms，比 save/load 快 101x。100Gb 跨节点 Rust mover 可达 92.09Gb/s CRC-verified，1.67GB 迁移约 141-146ms，满足 400ms block horizon。Python 初版 251ms 也能 3/3 seeds bit-exact 继续。Incast-aware admission 在 1.4x offered load 前零 miss；lossless ANS 可压缩 35.6%-44.6% state。

## Value
对模型研究不是核心，但对部署交互式世界模型非常有参考价值：它明确指出 world model serving 的关键资源不是请求，而是可迁移、可校验的隐式状态。若未来做在线交互视频/3D 世界模型，这类系统约束会影响架构选择。

## Strengths
问题定义准确，量化了 state size、dirty rate 和迁移门限；强调 bit-exact continuity；系统实验具体。

## Weaknesses
与世界模型算法本身关系弱；只在有限模型/硬件/网络配置上验证；跨架构 bit-exact 不成立；压缩迁移还未完全集成。

## Future Work
作者列出的局限也是未来方向：把 serving loop 与 100Gb verified mover 完全集成，扩展到真实生产 trace、多后端和更大 fleet，并改进跨架构一致性与压缩迁移。

## Rating
创新度评分：3/5 - 系统问题定义和实测扎实，但属于 serving 基础设施创新。
相关度评分：1/3 (Tangential) - 服务交互式世界模型相关，但不研究视频/3D/隐式世界模型本体。

## TL;DR
